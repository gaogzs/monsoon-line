# 机库俯视识别图

数据 `js/planform.js` · 调用点 `js/game.js` 的 `buildHangar()` · 预览器 `tools/render-planform.js`

---

## 它解决什么问题

机库里原本只有文字和统计条，玩家看不出三架飞机"长得"有什么不一样。
右上角一张俯视识别图之后，外形差异一眼可辨：

| 机型 | 俯视特征 |
|---|---|
| DB-11 军舰鸟 | **变后掠翼** —— 后掠三角，翼根在中后部 |
| D-14 旗鱼 | **菱形翼** —— 大后掠，前后缘对称收成菱形 |
| G-6 鲣鸟 | **平直大展弦比翼** —— 展弦比最大，可挂 6 个挂点 |

而且它**随所选特殊武器实时改变**，等于把挂载配置可视化了 ——
选了反舰弹会看到四枚明显更长的弹体，选了电子战吊舱会看到方头方脑的吊舱。

## 画风

取向是**老式军事识别图 / 技术插图**：

- 深底（`#070d12`，与界面同色）
- 单色细线勾勒，**不用渐变、不用阴影、不用色块**
- 淡青网格底纹
- 翼展 / 机长尺寸标注
- 内部只保留必要结构线：翼梁、机身分段、进气道、座舱盖、尾喷口

配色沿用界面那一套：

| 颜色 | 用途 |
|---|---|
| `#8fa8b8` | 主轮廓 |
| `rgba(143,168,184,.42)` | 内部结构线 |
| `rgba(143,168,184,.18)` | 参考虚线 |
| `#4fe08a` | 挂载 |
| `#ffb03a` | 机炮 |
| `#45d6ff` | 座舱盖 |

**不要给它加填色或阴影。** 界面其余部分是线框风格，
任何一处上色块都会显得格格不入。

## 坐标系

和三维模型一致：**机头朝 +y（图上朝上），右翼朝 +x**，单位米。

绘制时按 `k = min((W-padX*2)/span, (H-padY*2)/len)` 缩放，
所以翼展大的机型在图上确实更宽 —— 相对比例是真的。

---

## 数据结构

```js
PLANFORM.planes.c11 = {
  span, len,                    // 用于自动缩放与尺寸标注
  outline: [[x,y], ...],        // 闭合主轮廓
  lines:   [[[x,y],[x,y]], ...],// 内部结构线
  dash:    [[[x,y],[x,y]], ...],// 参考虚线
  fills:   [{ pts:[[x,y]...], a }],  // 需要淡填充的面（座舱盖）
  hardpoints: [{ x, y }, ...],  // 挂点
  cannon:  { x, y }             // 机炮
};
```

**加新机型时**：在 `P` 里加一份数据，键名必须等于 `AIRCRAFT[].model`。
`preflight()` 会检查这件事，漏了会报"缺少俯视识别图数据"。

## 挂载点标注

每组挂载点引一条折线到画布**左右两侧的标注栏**：

```
GROUP A
TOR-2 ×8  ─────┐
               │
     ●─────────┘
```

- 偶数索引标右侧、奇数索引标左侧 —— **全堆在一侧会四线交叉穿过机身**
- 线上方写 `GROUP <组号>`，下方写武器型号与总携弹量；空置写"空置"
- 当前正在编辑的那一组用**琥珀色**高亮
- 锚点直接取自 `AIRCRAFT[].hardpointGroups[].pts`，不另建一份坐标

标注栏各占 132 px（`padL` / `padR`），缩放时留出来。

## 挂载外形

`drawStore(g, x, y, kind, k, style)` 按武器 `kind` 画不同外形：

| kind | 外形 |
|---|---|
| `aam` | 尖头细弹体 + 中段弹翼 + 尾翼 |
| `asm` | 更粗更长，多一圈助推器标记 |
| `agm` | 中等弹体 + 弹翼 |
| `bomb` | 圆头钝尾（二次曲线），加尾翼横线 |
| `ecm` | 方头吊舱，带舱段分隔线 |
| `dew` | 同 ecm，但前方多一个发射孔径圈 |

> `ecm` / `dew` 一开始漏在分派表外，被画成了普通导弹。加新武器类型时
> **记得在这里补一个分支**，否则外观不会变。

## 可变后掠翼

DB-11 的轮廓数据里有 `sweepAlt`（展开位的前缘与后缘）和 `sweepPivot`
（铰链位置）。主轮廓画的是**后掠位**，展开位用青色虚线叠加，
再加一个 `sweepLabel` 文字标注。

这样"机翼会动"这件事在静态识别图上就看得见了 ——
只画一个位置的话，玩家不会知道这架飞机有变后掠设计。

长度取自 `STORE_LEN` 表，乘 `k` 折算成像素 ——
所以反舰弹在图上确实比格斗弹长。

## 装填进度

战斗 HUD 右下角那张小图上，每个挂载点显示自己的装填进度 ——
**一个挂载点就是一个发射槽**，所以进度是逐个算的：

```
刚发射       装填中        就绪
  ╷           ▁▁           ██
  ▫           ██           ██    ← 亮绿从下往上填
  ▫           ██           ██
```

- **刚发射 = 空壳**（只剩一层暗绿轮廓）
- 亮绿**从下往上**按进度填回来
- **填满 = 可以再打**

**方向很重要**：进度条要朝着"能打"的方向生长。
反过来（先满、然后慢慢变空）读起来像是"越打越有"，
和真实状态正好相反 —— 这正是它早期版本的问题。

进度条就是这个弹体本身，不另找地方放一条。
`opts.cd` 的形状是 `{ 武器 id: [槽1就绪度, 槽2就绪度, ...] }`，
就绪度 **1 = 满、0 = 空**（注意是**就绪度**，不是剩余冷却）。

## 一个容易画错的地方

**挂载必须先画，轮廓后画。**

如果反过来（先轮廓再叠挂载），导弹会像浮在机翼**上面**；
先画挂载让轮廓线压过去，才读作"挂在翼下"。

识别图就是这么画的，不要改这个顺序。

## 预览器

这台开发机没有浏览器，"画风"这种东西光看代码判断不了。
所以有 `tools/render-planform.js`：

```bash
node tools/render-planform.js     # 输出到 tools/preview/*.png
```

它实现了一个最小的 Canvas 2D 子集（路径、描边、扫描线填充、
二次曲线、虚线）、一个抗锯齿光栅器，和一个 PNG 编码器
（IHDR/IDAT/IEND + CRC32 + zlib），然后**加载真正的 `js/planform.js`**
把每个机型 × 每种挂载渲染成图片。

用的就是游戏里那份绘制代码，所以预览和实际效果一致。

**改动俯视图数据后建议跑一次预览**，肉眼确认形状没画歪。

> 预览器不支持 `fillText`，所以生成的图里没有文字标注。
> 游戏里有。这是预览器的已知限制，不影响正确性。
