# 机库俯视识别图

数据 `js/planform.js`（740 行）· 调用点 `js/game.js` 的 `buildHangar()`
与 `js/hud.js` 的 `drawStores()` · 预览器 `tools/render-planform.js`

---

## 它解决什么问题

机库里原本只有文字和统计条，玩家看不出几架飞机"长得"有什么不一样。
右上角一张俯视识别图之后，外形差异一眼可辨。
`P` 里现有 **6 个机型**，键名与 `AIRCRAFT[].model` 一一对应：

| 键 | 机型 | 翼展 / 机长（m） | 俯视特征 |
|---|---|---|---|
| `c11` | DB-11 军舰鸟 | 15.2 / 20.4 | **变后掠翼** —— 后掠三角，翼根在中后部 |
| `c14` | D-14 旗鱼 | 13.8 / 22.9 | **菱形翼** —— 大后掠，前后缘对称收成菱形 |
| `s6` | G-6 鲣鸟 | 17.2 / 19.4 | **平直翼** —— 翼展最大，3 组共 6 个挂点 |
| `c9` | F-9 海燕 | 13.2 / 22.9 | **三角翼** —— 机身最细长，双尾喷口 |
| `c21` | D-21 贼鸥 | 13.8 / 21.4 | **无尾菱形翼** —— 后缘前掠，扁平尾缘 |
| `c33` | D-33 信天翁 | 16.4 / 19.6 | **前掠翼** —— 翼尖在翼根之前 |

表是按 `model` 查的，不是按 `id`：`AIRCRAFT` 17 条里，NPC 机型 `k8`（XAMSI「潮线」）
的 `model` 是 `'c14'`，所以它也能取到旗鱼这份数据 —— **实际有俯视图的是 7 型**
（6 架可驾驶 + `k8`）。其余 10 型 NPC 没有数据，单位详情页对它们不显示这一节
（见 [unitview.md](unitview.md)）。借用意味着 `k8` 的识别图就是 D-14 的外形，
这与它在三维里用 `c14` 模型是同一个取舍。

而且它**随所选特殊武器实时改变**，等于把挂载配置可视化了 ——
选了反舰弹会看到明显更长的弹体，选了电子战吊舱会看到方头方脑的吊舱。

## 画风

取向是**老式军事识别图 / 技术插图**：

- 深底（`#070d12`，与界面同色），叠一层 22 px 间距的淡青网格
- 单色细线勾勒，**不用渐变、不用阴影、不用色块**
- 翼展 / 机长尺寸标注
- 内部只保留必要结构线：翼梁、机身分段、进气道、座舱盖、尾喷口

配色沿用界面那一套，全部写在 `paint()` 开头的局部常量里：

| 常量 | 颜色 | 用途 |
|---|---|---|
| `INK` | `#8fa8b8` | 主轮廓（线宽 1.8） |
| `INK2` | `rgba(143,168,184,0.42)` | 内部结构线（线宽 1） |
| `INK3` | `rgba(143,168,184,0.18)` | 参考虚线（`setLineDash([5,5])`） |
| `STORE` | `#4fe08a` | 挂载 |
| `AMBER` | `#ffb03a` | 机炮 / 当前编辑的高亮 |
| `CY` | `#45d6ff` | 座舱盖填充与描边 |
| 网格 | `rgba(69,214,255,0.055)` | `draw()` 里的底纹 |

**不要给它加填色或阴影。** 界面其余部分是线框风格，
任何一处上色块都会显得格格不入。唯一允许的填充是
`fills` 里的座舱盖（`rgba(69,214,255,a)`，`a` 约 0.18–0.20）。

## 坐标系

和三维模型一致：**机头朝 +y（图上朝上），右翼朝 +x**，单位米。

绘制时按

```
k = min((W - padL - padR) / span, (H - padY*2) / len)
```

缩放，再套 `TX(x) = cx + x*k`、`TY(y) = cy - y*k`（屏幕 y 向下，
所以取负）。所以翼展大的机型在图上确实更宽 —— 相对比例是真的。

留白分两种模式：

| | `padL` / `padR` | `padY` |
|---|---|---|
| 机库大图（默认） | 132 / 132 | 44 |
| 紧凑模式（`opts.compact`，HUD 用） | 10 / 10 | 10 |

`cx = padL + (W-padL-padR)/2`，`cy = H/2`。两种模式下 `padL == padR`，
所以 `cx` 就是 `W/2`，图在画布水平居中；`cy` 取正中。

## 数据结构

```js
PLANFORM.planes.c11 = {
  span, len,                    // 用于自动缩放与尺寸标注
  outline: [[x,y], ...],        // 闭合主轮廓
  lines:   [[[x,y],[x,y]], ...],// 内部结构线
  dash:    [[[x,y],[x,y]], ...],// 参考虚线（中心线、铰链参考）
  fills:   [{ pts:[[x,y]...], a }],  // 需要淡填充的面（座舱盖）
  sweepAlt:   [[[x,y],[x,y]], ...],  // 可选：可变后掠的展开位
  sweepPivot: { x, y },              // 可选：铰链位置
  sweepLabel: '可变后掠 11°–35°',    // 可选：文字标注
  cannon:  { x, y }             // 机炮
};
```

**注意这里没有 `hardpoints` 字段。** 挂点位置只有一份数据源，
就是 `AIRCRAFT[].hardpointGroups[].pts`（同样是机头 +y 的俯视坐标）。
识别图用 `groupsOf(ac)` 取组、用 `grp.pts` 当锚点，
`data.js` 里也注明"同时也是机库俯视识别图上 Group 引线的锚点 ——
单一数据源"。**不要在 `planform.js` 里再抄一份坐标。**

`c11` 额外带 `sweepAlt` / `sweepPivot` / `sweepLabel` 三个字段
（详见"可变后掠翼"）；其余五个机型只有 `cannon`，没有挂点字段。

`planform.js` 对外只返回三个东西：

```js
return { planes: P, draw: draw, paint: paint };
```

**加新机型时**：在 `P` 里加一份数据，键名必须等于 `AIRCRAFT[].model`。
`game.js` 的 `preflight()` 会检查这件事，漏了会报"缺少俯视识别图数据"——
但它**跳过 `npcOnly` 的机型**（`if (!ac.npcOnly && !PLANFORM.planes[ac.model])`），
所以敌方制式机、支援机不进机库、也不需要这张图。

## 公开 API 与机库对接

两份绘制代码，一个入口：

- `draw(cv, ac, loadout, activeGroup, cd)` —— **机库大图**。
  自己取 2D 上下文，`clearRect` + 填 `#070d12` + 画网格，
  然后委托 `paint(g, 0, 0, W, H, ...)` 铺满整个 canvas。
- `paint(g, bx, by, bw, bh, ac, loadout, opts)` —— 把识别图画进
  **任意 2D 上下文里的一个矩形区域**。`opts` 三个字段：
  - `active`：当前高亮的挂载点组 id
  - `cd`：`{ 武器 id: [槽就绪度, ...] }`（见"装填进度"）
  - `compact`：紧凑模式，省掉标注栏与尺寸线（HUD 用）

对接方式：

| 位置 | 调用 |
|---|---|
| 机库（`game.js` `buildHangar()`） | `PLANFORM.draw(document.getElementById('planCv'), ac, lo, activeHpGroup)` |
| 战斗 HUD 右下角（`hud.js` `drawStores()`） | `PLANFORM.paint(ctx, bx, by, size, size, p.ac, p.loadout, { compact: true, cd: cd })` |

HUD 那句的 `cd` 由 `drawStores()` 现算：把每条挂载的剩余冷却
`arr[j] / w.cd` 夹到 0..1 再取 `1 -`，得到**就绪度**放进数组。
两边共用同一份 `paint()`，所以挂点位置与武器外形永远一致 ——
分成两份写的话，两边一定会慢慢长得不一样。

机库图下方的说明文字由 `game.js` 写在 `planCap` 里
（"绿色为挂载，琥珀为当前编辑的挂载点组，青色虚线为可变后掠翼的展开位"）。

## 挂载点标注

每组挂载点引一条折线到画布**左右两侧的标注栏**：

```
GROUP A
TOR-2 ×8  ─────┐
               │
     ●─────────┘
```

- 折线走 `锚点 → (锚点 ± 10, ly) → (bendX, ly) → (edge, ly)`
- `ly = 44 + rank*34`，`rank = floor(组索引 / 2)`
- **偶数索引标右侧、奇数索引标左侧** —— 全堆在一侧会四线交叉穿过机身
- 锚点取该组 `pts` 的首个（右侧）或末个（左侧），不另建一份坐标
- 线上方写 `GROUP <组号>`，下方写 `武器名 + ' ×' + 总携弹量`；
  空置写"空置"
- 当前正在编辑的那一组用**琥珀色**高亮（引线加粗到 1.5、弹体线宽 2）
- 总携弹量 = `挂点数 × (武器.perPoint || 1)`

标注栏各占 132 px（`padL` / `padR`），缩放时留出来；
右侧 `edge = W-14`、`bendX = W-122`，左侧镜像成 `14` / `122`。

文本用 10 px `Consolas,monospace`，靠边对齐（右侧 `right`、左侧 `left`），
免得跑出画布。

## 挂载外形

`drawStore(g, x, y, kind, k, style)` 按武器 `kind` 画不同外形，
`style.line` 决定线宽。长度查 `STORE_LEN`、宽度按机型折算：

| kind | `STORE_LEN`（m） | 宽度 `W` | 外形 |
|---|---|---|---|
| `aam` | 3.4 | `max(2, 0.22k)` | 尖头细弹体 + 中段弹翼 + 尾翼 |
| `asm` | 4.6 | `max(2.5, 0.30k)` | 更粗更长，尾部多一圈助推器横线 |
| `agm` | 4.0 | `max(2.2, 0.26k)` | 中等弹体 + 弹翼 |
| `bomb` | 2.2 | `max(3, 0.48k)` | 圆头钝尾（二次曲线），加尾翼横线 |
| `ecm` | 3.2 | `max(4, 0.62k)` | 方头吊舱，带两道舱段分隔线 |
| `dew` | 3.6 | `max(4.5, 0.78k)` | 同 ecm，但前方多一个发射孔径圈 |
| 其它 | 3.0 | `max(2, 0.30k)` | 按 `aam` 画 |

长度 = `STORE_LEN[kind] * k`，`k` 是像素/米，所以反舰弹在图上
确实比格斗弹长。`isPod(kind)` 把 `ecm` / `dew` 归到方头吊舱一类。

> `ecm` / `dew` 一开始漏在分派表外，被画成了普通导弹。加新武器类型时
> **记得在这里补一个分支**，否则外观不会变。

弹体一律**头部朝上**：屏幕 y 向下增大，所以头部取 `y - L/2`、
尾部取 `y + L/2`。写反过一次。

## 可变后掠翼

只画一次、只属于 `c11` 的三个字段：

```js
sweepAlt: [
  [[1.30, 2.4], [7.8, 1.2]],   // 展开位前缘
  [[1.50, -3.4], [7.8, -1.4]]  // 展开位后缘
],
sweepPivot: { x: 1.45, y: 1.9 },
sweepLabel: '可变后掠 11°–35°'
```

主轮廓画的是**后掠位**，`sweepAlt` 用**青色虚线**叠加展开位：

- 线色 `rgba(69,214,255,0.42)`，`setLineDash([3,4])`
- **左右各镜像画一条**（`x` 取正负），否则只有半边机翼"会动"
- 铰链点画成 `rgba(69,214,255,0.75)` 的实心圆，半径 2.4，同样镜像两个
- `sweepLabel` 用 10 px 字体写在画布左上角 `(12, 18)`，
  颜色 `rgba(69,214,255,0.62)`

这样"机翼会动"这件事在静态识别图上就看得见了 ——
只画一个位置的话，玩家不会知道这架飞机有变后掠设计。

（`sweepAlt` 在 `paint()` 里画在主轮廓**之前**，所以轮廓线压在它上面。）

## 装填进度

战斗 HUD 右下角那张小图上，每个挂载点显示自己的装填进度 ——
**一个挂载点就是一个发射槽**，所以进度是逐个算的：

```
刚发射       装填中        就绪
  ╷           ▁▁           ██
  ▫           ██           ██    ← 亮绿从下往上填
  ▫           ██           ██
```

- **刚发射 = 空壳**（只剩一层 `rgba(79,224,138,0.20)` 的暗绿轮廓）
- 亮绿**从下往上**按进度填回来
- **填满 = 可以再打**

**方向很重要**：进度条要朝着"能打"的方向生长。
反过来（先满、然后慢慢变空）读起来像是"越打越有"，
和真实状态正好相反 —— 这正是它早期版本的问题。

进度条就是这个弹体本身，不另找地方放一条。
`opts.cd` 的形状是 `{ 武器 id: [槽1就绪度, 槽2就绪度, ...] }`，
就绪度 **1 = 满、0 = 空**（注意是**就绪度**，不是剩余冷却）。

`paint()` 里的实现：`ready = clamp(cdArr[pi] ?? 1, 0, 1)`，
没有进度信息时当满的；`ready >= 0.998` 直接画实心弹体，
否则先用暗色画一遍轮廓，再用 `clip()` 裁出
`(px-k*1.8, py+Lc/2-Lc*ready, k*3.6, Lc*ready)` 这块矩形
把亮绿弹体重叠上去。

> 函数头注释里还写着 `opts.cd { 武器 id: 0..1 }，1 = 刚打完，0 = 已就绪`——
> **那是过时注释，和代码相反**。代码与 HUD 都按"1 = 就绪"处理。

## 一个容易画错的地方

**挂载必须先画，轮廓后画。**

`paint()` 的顺序是：座舱盖填充 → 参考虚线 → **挂载** → 展开位虚线 →
内部结构线 → 主轮廓 → 挂载点标注 → 机炮 → 尺寸线 → 方向提示。

如果反过来（先轮廓再叠挂载），导弹会像浮在机翼**上面**；
先画挂载让轮廓线压过去，才读作"挂在翼下"。
识别图就是这么画的，不要改这个顺序。

## 预览器

这台开发机没有浏览器，"画风"这种东西光看代码判断不了。
所以有 `tools/render-planform.js`（640 × 440）：

```bash
node tools/render-planform.js     # 输出到 tools/preview/*.png
```

它实现了一个最小的 Canvas 2D 子集（路径、描边、`quadraticCurveTo`、
`arc`、扫描线填充、虚线）、一个抗锯齿光栅器，和一个 PNG 编码器
（IHDR/IDAT/IEND + CRC32 + zlib），然后**加载真正的 `js/planform.js`**
（连同 `data.js`、`math3d.js`、`models.js`）调用 `PLANFORM.draw()`。

输出文件名三种：`<机型>-default.png`、`<机型>-clean.png`、
`<机型>-<武器 id>.png`（把该武器填满所有挂得下的组）。
`default` 用 `ac.defaultLoadout`，`clean` 是空挂载。

**改动俯视图数据后建议跑一次预览**，肉眼确认形状没画歪。

> 预览器不支持 `fillText`（被实现为空函数），所以生成的图里没有文字标注
> ——`GROUP n`、`翼展 x m`、`可变后掠 11°–35°` 在预览里都看不到。
> 游戏里有。这是预览器的已知限制，不影响形状正确性。
>
> 它对 `AIRCRAFT` 是**全表遍历**的，所以那些没有俯视数据的机型
> （`npcOnly` 的制式机、轰炸机等）也会各生成一张图，
> 但画面里只有网格底——连 `paint()` 的 "NO DATA" 提示都是 `fillText`，
> 同样被吞掉。看到空白图是正常的，只代表这个机型本来就没有识别图。
>
> `clip()` 没有实现；预览永远不传 `cd`，所以 `paint()` 里那条裁剪分支
> 不会被走到，不会报错。
