# 机库俯视识别图

数据 `js/planform.js` · 调用点 `js/game.js` 的 `buildHangar()` · 预览器 `tools/render-planform.js`

---

## 它解决什么问题

机库里原本只有文字和统计条，玩家看不出三架飞机"长得"有什么不一样。
右上角一张俯视识别图之后，外形差异一眼可辨：

| 机型 | 俯视特征 |
|---|---|
| C-11 军舰鸟 | **变后掠翼** —— 后掠三角，翼根在中后部 |
| C-14 旗鱼 | **菱形翼** —— 大后掠，前后缘对称收成菱形 |
| S-6 鲣鸟 | **平直大展弦比翼** —— 展弦比最大，可挂 6 个挂点 |

而且它**随所选特殊武器实时改变**，等于把挂载配置可视化了 ——
选了反舰弹会看到四枚明显更长的弹体，选了电子战吊舱会看到方头方脑的吊舱。

## 画风

取向是**老式军事识别图 / 技术插图**：

- 深底（`#070d12`，与界面同色）
- 单色细线勾勒，**不用渐变、不用阴影、不用色块**
- 淡青网格底纹
- 翼展 / 机长尺寸标注
- 内部只保留必要结构线：翼梁、机身分段、进气道、座舱盖、尾喷口

配色沿用界面那一套：

| 颜色 | 用途 |
|---|---|
| `#8fa8b8` | 主轮廓 |
| `rgba(143,168,184,.42)` | 内部结构线 |
| `rgba(143,168,184,.18)` | 参考虚线 |
| `#4fe08a` | 挂载 |
| `#ffb03a` | 机炮 |
| `#45d6ff` | 座舱盖 |

**不要给它加填色或阴影。** 界面其余部分是线框风格，
任何一处上色块都会显得格格不入。

## 坐标系

和三维模型一致：**机头朝 +y（图上朝上），右翼朝 +x**，单位米。

绘制时按 `k = min((W-padX*2)/span, (H-padY*2)/len)` 缩放，
所以翼展大的机型在图上确实更宽 —— 相对比例是真的。

---

## 数据结构

```js
PLANFORM.planes.c11 = {
  span, len,                    // 用于自动缩放与尺寸标注
  outline: [[x,y], ...],        // 闭合主轮廓
  lines:   [[[x,y],[x,y]], ...],// 内部结构线
  dash:    [[[x,y],[x,y]], ...],// 参考虚线
  fills:   [{ pts:[[x,y]...], a }],  // 需要淡填充的面（座舱盖）
  hardpoints: [{ x, y }, ...],  // 挂点
  cannon:  { x, y }             // 机炮
};
```

**加新机型时**：在 `P` 里加一份数据，键名必须等于 `AIRCRAFT[].model`。
`preflight()` 会检查这件事，漏了会报"缺少俯视识别图数据"。

## 挂载外形

`drawStore(g, x, y, kind, k, style)` 按武器 `kind` 画不同外形：

| kind | 外形 |
|---|---|
| `aam` | 尖头细弹体 + 中段弹翼 + 尾翼 |
| `asm` | 更粗更长，多一圈助推器标记 |
| `agm` | 中等弹体 + 弹翼 |
| `bomb` | 圆头钝尾（二次曲线），加尾翼横线 |
| `pod` | 方头吊舱（ECM / DEW） |

长度取自 `STORE_LEN` 表，乘 `k` 折算成像素 ——
所以反舰弹在图上确实比格斗弹长。

## 一个容易画错的地方

**挂载必须先画，轮廓后画。**

如果反过来（先轮廓再叠挂载），导弹会像浮在机翼**上面**；
先画挂载让轮廓线压过去，才读作"挂在翼下"。

识别图就是这么画的，不要改这个顺序。

## 预览器

这台开发机没有浏览器，"画风"这种东西光看代码判断不了。
所以有 `tools/render-planform.js`：

```bash
node tools/render-planform.js     # 输出到 tools/preview/*.png
```

它实现了一个最小的 Canvas 2D 子集（路径、描边、扫描线填充、
二次曲线、虚线）、一个抗锯齿光栅器，和一个 PNG 编码器
（IHDR/IDAT/IEND + CRC32 + zlib），然后**加载真正的 `js/planform.js`**
把每个机型 × 每种挂载渲染成图片。

用的就是游戏里那份绘制代码，所以预览和实际效果一致。

**改动俯视图数据后建议跑一次预览**，肉眼确认形状没画歪。

> 预览器不支持 `fillText`，所以生成的图里没有文字标注。
> 游戏里有。这是预览器的已知限制，不影响正确性。
