## 控制律：最少时间转向

**整个 AI 只有一个控制律**，`steerTo(aircraft, desiredDir, out, state)`。
玩家用鼠标引导时也走这一个函数。

它的逻辑来自真实空战：**先滚转对齐，再全力拉杆**。

```
① 滚转：把目标滚进机体的俯仰平面，让它出现在"正上"方向
② 俯仰：对齐度越高，拉得越满
```

### ① 滚转

把目标方向分解到机体坐标 `(rx, ux, fx)`，则让它落到"正上方"
所需的滚转角是：

```js
rollErr = atan2(-rx, ux);          // ∈ [-π, π]
rollCmd = clamp(-rollErr * 2.8, -1, 1);
```

**方向锁存**：目标接近正下方时 `rx` 会在 0 附近抖，导致
满左滚 / 满右滚来回横跳。所以当 `|rollErr| > 2.55` 时锁住转向，
转过半圈再解锁：

```js
if (st) {
  if (Math.abs(rollErr) > 2.55) {
    if (!st.rollLock) st.rollLock = (rollErr >= 0) ? 1 : -1;
    rollErr = st.rollLock * 3.14;
  } else st.rollLock = 0;
}
```

玩家对象自带 `rollLock` 字段（初始 `undefined`，视为 falsy）。

### ② 俯仰

关键不是"目标偏了多少度"，而是**目标在上半平面还是下半平面**：

```js
lateral = sqrt(rx*rx + ux*ux);
up = clamp(ux / lateral, -1, 1);      // +1 正上，0 正侧，-1 正下
mag = clamp(off * 2.3, 0, 1);

if (up >= 0) pitchCmd = mag * (0.55 + 0.45 * sqrt(up));   // 拉杆
else         pitchCmd = mag * 0.18 * (1 + up);            // 几乎不拉，交给滚转
```

### 情况 A：前下方目标直接推杆

上面那套"滚转对齐再拉杆"有个致命的反例：**目标在机头斜前方偏下**。

此时 `ux < 0`，`rollErr = atan2(-rx, ux)` 趋近 ±π，滚转指令直接饱和成满舵——
玩家把鼠标轻轻往下推一点，飞机会先滚半圈、然后开始抬头，完全不是"俯下"。

所以前面先拦一道：

```js
if (fx > 0.25 && ux < -0.05) {
  var down = clamp(-ux, 0, 1);
  out.pitch = -mag * (0.55 + 0.45 * Math.sqrt(down));    // 推杆
  out.roll  = clamp(-atan2(rx, -ux) * 2.0, -1, 1) * 0.5; // 只做小幅修正
  return out;
}
```

**判据用 `ux` 而不是归一化后的 `up`**：`up = ux / √(rx²+ux²)` 在小离轴角时
几乎恒为 ±1，拿它当阈值基本永远命中不了。

`smoke.js` 里有三个方向的验证：前下方→俯下、前上方→抬头、正侧方→滚转。

### 这条控制律修过什么

早期版本用的是：

```js
align = 1 - min(1, |rollErr| / 2.0);
pitchCmd = mag * (0.30 + 0.70 * align);
```

问题在于**用滚转角大小去削弱俯仰**。目标在正侧方时 `align ≈ 0.22`，
拉杆只剩 45%——飞机是"滚过去再慢慢蹭"，而不是
"滚筒到位后一把拉满做最大过载转向"。

对照一下就很清楚：想要"向左下方急转"时，

| | 旧 | 新 |
|---|---|---|
| 滚转指令 | 满左滚 | 满左滚 |
| 同时的俯仰 | 45% | **4%**（几乎纯滚转） |
| 对齐后俯仰 | 回到 100% 需要时间 | **立即 87% → 100%** |

新逻辑在滚转阶段几乎不收杆，反而让整个动作更快。

## 状态机

三种模式，优先级从高到低：

| 模式 | 触发 | 行为 |
|---|---|---|
| `evade` | 有以自己为目标的导弹在 4.2 km 内 | 把导弹放 3/9 线，保能量；< 900 m 时俯冲拖入稠密大气；同时放干扰弹 |
| `extend` | 血量 < 25%（有 0.4%/帧 概率触发） | 背向最近的敌人加力脱离 |
| `pursue` | 默认 | 追最近的敌人 |

规避是**抢占式**的：一旦发现来袭导弹立刻切模式，`evadeT` 计时器
确保不会一帧就切回来。

## 目标选择

每 0.35–1.25 秒重选一次（间隔随技能降低而变长），规则分角色：

- **敌方**：最近的敌机，搜索半径 15 km
- **僚机 + `focus` 指令**：跟随长机锁定的目标
- **僚机 + `cover` 指令**：优先挑正在锁定长机的敌机
- **僚机 + `spread` 指令**：自由接战，半径 11 km

## 编队

僚机在无目标时跟随长机的**机体坐标系**中的固定槽位：

```js
slot = { dx: -170, dy: 25, dz: -260 };
waypoint = lead.pos + lead.right*dx + lead.fwd*dz + (0,dy,0);
```

用长机的机体坐标而不是世界坐标，所以编队会跟着长机滚转和转向。

## 无人僚机

`role: 'drone'` 与 `role: 'wingman'` 的差别不是参数，而是**有没有判断力**。

有人僚机会自主选目标、会追出去接战；无人僚机不会 —— 它只有三条规则：

**1. 目标只能来自长机授权**

```js
if (s.role === 'drone') {
  s.target = (lead.alive && lead.target && lead.target.alive) ? lead.target : null;
}
```

长机没锁定，它就一弹不发。设定里它是"自己看不见任何东西，
全靠长机把目标参数喂过来"。

**2. 机动只跟编队位置有关**

即使拿到了目标，它也**不追出去** —— 永远待在编队槽位上，
目标只用来决定"能不能打"。
它的价值在于替长机挡导弹、探路、把挂架打空，追出去就全没了。

**3. 长机阵亡后就地盘旋**

```js
var tan = a.right;
desired = norm(V(tan.x, climb, tan.z));   // 取切向 → 持续转圈
```

不接管战局、不自主选目标。这不是能力不足，是它压根没有那套东西。

> 回归测试 `smoke.js` 里有四项断言：未授权时无目标、
> 授权后继承同一目标、长机阵亡后不向敌人逼近、长机健在时不脱队。

## 开火判定

### 机炮

```js
range = (y > 18000) ? weapon.highRange : weapon.range;
cone  = 0.028 + (1 - skill) * 0.02;
fire  = dist < range * 0.9 && off < cone * 3.2;
```

### 导弹

三个条件都满足才发射：

1. 在锁定锥内（高空收窄 20%）
2. 距离 < `lockDist`，且超过最小距离（冲压弹 1400 m，其他 700 m）
3. `random() < 0.35 + skill * 0.45`

发射后进入 2.6–5.2 秒冷却（技能越高越短）。

### 侦察 / 播撒构型

`behavior === 'recon'` 且血量 > 88% 时**完全不还手**，
只跑。这用于 M1 的测绘机和 M3 的播撒机——它们是任务目标，
不该像战斗机一样缠斗。

## 技能等级

`AI.attach(a, { skill })`，0..1：

| 影响 | 低技能 | 高技能 |
|---|---|---|
| 重选目标间隔 | 1.25 s | 0.35 s |
| 机炮散布锥 | 0.048 | 0.028 |
| 导弹发射意愿 | 35% | 80% |
| 发射冷却 | 4.6 s | 2.6 s |

现有数值：测绘机 0.25–0.32、普通敌机 0.5–0.6、护航 0.6、
M2 伏击长机 0.72、**干井（DRYWELL）0.96**。

## 与玩家共用控制律的后果

`steerTo` 同时服务 AI 与玩家的鼠标引导，好处是**手感一致**：
敌人做机动的方式和玩家一样。

代价是**改它要同时验证两边**。特别是：
- 滚转锁存依赖调用方传入的 `state` 对象，AI 传的是机自己
- `mag * 2.3` 的饱和点同时影响玩家灵敏度和 AI 转向速率
