# 渲染管线

代码：`js/render.js` · 相机与投影数学在 `js/math3d.js`

---

## 为什么不用 WebGL

"低多边形 + 画家算法"在 Canvas 2D 上跑得动，而且白捡了三个好处：

1. **零依赖**。不用 Three.js，不用写着色器，不用处理 GL 上下文丢失
2. **`file://` 直接可跑**。WebGL 在某些浏览器下对本地文件有额外限制
3. **low-poly 的颗粒感正好符合"低质量小游戏"的自我定位**——
   如果上 WebGL 做一个半吊子的 PBR，反而显得寒酸

**什么时候该换掉它**：如果模型面数需要超过约 3000 面/帧，
或者需要后处理（辉光、景深）。目前远没到。

## 相机模型

相机**不是矩阵**，是：

```js
{ pos, fwd, up, right, focal, cx, cy, w, h, near, far }
```

`fwd / up / right` 是三个互相正交的单位向量，`right = up × fwd`。

世界点 → 相机空间：

```js
d  = worldPoint - cam.pos
camX = d·right    camY = d·up    camZ = d·fwd
```

屏幕坐标：

```js
sx = cx + focal * camX / camZ
sy = cy - focal * camY / camZ        // 屏幕 y 向下，所以取负
focal = (h/2) / tan(fovY/2)
```

**为什么不用矩阵**：矩阵写法需要约定行/列主序、乘法顺序、
是否含平移。用基向量写没有歧义，调试时可以直接把向量打进控制台看。

## 近平面裁剪

`camZ < near`（默认 0.6 m）的点在相机后方，投影会爆炸。

- **线段**（地面网格）：`M3.clipSeg()` 求交点后截断
- **多边形**（模型面）：Sutherland–Hodgman 单平面裁剪，
  在 `pushModel()` 内联实现

**注意**：裁剪必须在**相机空间**做（用 `camZ` 判断），
不能在屏幕空间做。屏幕空间已经丢失了深度符号。

## 画家算法

不做背面剔除。每帧把所有面塞进一个池，按**面质心的相机空间深度**
降序排序，从远到近绘制。

```js
arr.sort(function (a, b) { return b.d - a.d; });
```

**为什么不做背面剔除**：低多边形模型常常有洞、绕序不一定一致
（镜像的翼面尤其容易出错），剔除会导致随机缺面，而且很难排查。
代价是绘制量翻倍。

**补接缝**：相邻多边形的共享边会露出背景，出现发丝状裂缝。
对策是对面数 ≤ 4、深度 < 900 的面额外描一次同色边（`lineWidth 0.7`）。

## 光照与大气透视

每个面的亮度：

```js
bright = 0.44 + 0.56 * |dot(worldNormal, LIGHT)|
```

取绝对值是为了双面照明——因为不剔除背面，法线方向可能朝内。

雾：

```js
fog = clamp((depth - 900) / (9000 - 900), 0, 0.82)
color = mix(baseColor, (150,176,196), fog)
```

颜色不是每帧拼字符串，而是**量化缓存**：亮度与雾浓度各取 16 档，
组合成 key 查表。见 `shade()`。

## 每帧顺序

```
Renderer.begin()
  ├─ 处理镜头抖动（受击时）
  ├─ 天空渐变（从地平线颜色到天顶）
  ├─ 云（五层）
  ├─ 地面（渐变填充 + 网格线）
  └─ ctx.save() + translate(抖动偏移)

pushModel() × N        ← 只收集，不绘制
Renderer.flush()       ← 排序 + 绘制全部面

Renderer.drawParticles()   ← globalCompositeOperation = 'lighter'
Renderer.end()
HUD.draw()             ← 在 restore 之后，所以 HUD 不跟着抖
```

**HUD 不抖**是有意的：抖动的画面 + 稳定的 HUD 才有"撞击感"，
两者一起抖只会让人晕。

## 地平线

追尾视角的相机 `up` 恒在世界 +Y 附近（见 [DESIGN.md](../DESIGN.md#53-相机不跟随滚转追尾视角)），
所以地平线永远是水平的，`horizonY()` 只需投影一个水平方向的远点。

**如果哪天改成跟随滚转**，天空和地面的绘制方式全部要重写：
需要画一个倾斜的地平线，把屏幕分成两半。

## 云

`CLOUD_LAYERS` 定义了**五层**云，覆盖 500 m 到 21400 m：

| 层 | 高度范围 | 说明 |
|---|---|---|
| 1 | 500 – 2600 | 低层积云 |
| 2 | 3200 – 6200 | 中层 |
| 3 | 6800 – 10200 | 中高层 |
| 4 | 10800 – 15200 | 高层 |
| 5 | 15800 – 21400 | 平流层薄云 |

**为什么必须分这么多层**：早期版本只有一层（700–2600 m），
而玩家在 M1 是 7600 m、M3 是 19500 m。云全部在脚下 5–18 km 处，
俯角超过 40°，落在 58° 垂直视场之外——**完全看不见**，
于是玩家在单色海面上失去了所有姿态参照。云在这个游戏里不是装饰，
是**滚转感知的唯一信息来源**。

云用**环绕相机的重复网格**渲染：种子位置固定，以 `CLOUD_CELL`（6400 m）
为周期铺在相机周围，只画 16 km 内、投影半径 6 px – 8×屏高 之间的。

透明度：`alpha = base * smoothstep(距离衰减)`，远处融进天空。
椭圆压扁系数随视线掠射角变化，避免看起来像贴在屏幕上的白片。

## 粒子

```js
{ pos, vel, life, life0, size, color, alive, grow, alpha, drag, grav }
```

用 `globalCompositeOperation = 'lighter'` 绘制，
所以爆炸、尾焰、干扰弹都是加色叠加，天然有发光感。

上限 900 个（`compact()` 里裁掉最旧的）。

## 性能

| 手段 | 位置 |
|---|---|
| 对象池 | `getP()` / `getFace()` |
| 颜色量化缓存 | `shade()` |
| 面积剔除（< 1.6 px²） | `pushModel()` |
| 距离剔除（> 16 km） | `drawClouds()` |

**瓶颈是 `ctx.fill()` 的调用次数**，不是 JS 数学。
要提速就先降面数。

## 参数速查

| 想改什么 | 在哪 |
|---|---|
| 视场角 | 设置页「视场角 FOV」，存在 `S.fov` |
| 镜头距离 / 高度 | 设置页，`S.camDist` / `S.camHeight` |
| 光照方向 | `render.js` 顶部 `LIGHT` |
| 雾的距离与颜色 | `FOG_NEAR` / `FOG_FAR` / `FOG_RGB` |
| 云的高度分层 | `CLOUD_LAYERS` |
| 云的数量 | `CLOUD_LAYERS[].n` |
| 地面网格间距 | `drawGround()` 里的 `G = 500` |
| 面剔除阈值 | `pushModel()` 里的 `area < 1.6` |
