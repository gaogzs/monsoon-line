# 挂载系统

数据 `js/data.js` · 逻辑 `js/game.js` · 显示 `js/hud.js` / `js/planform.js`

---

## 一句话

每架飞机有若干**成对的挂载点组**，每组独立选择装什么；
同一种武器占多个组时，**弹药池累加、齐射数 = 挂载点总数**。

---

## 为什么这么设计

"固定机炮 + 一个特殊武器槽"的问题是：玩家在机库里做的唯一决定
是"从三选一里挑一个"，机体本身几乎没有选择空间。

改成挂载点制之后：

- 同一架飞机能带出完全不同的任务配置（纯制空 / 混合 / 对地）
- 挂载点的适配限制（翼尖挂不了反舰弹）逼玩家做取舍
- 空挂架能换回一点机动性，于是"带多少"本身也是一个决定
- 基础短程弹也是可选项 —— 不带就没有，只能靠机炮

这是《僚机计划》那一脉的思路，比"选一个特殊武器"厚得多。

## 数据结构

### 挂载点组（在 `AIRCRAFT` 里）

```js
hardpointGroups: [
  { id: 'A', label: '翼尖', kind: 'tip',
    pts: [{ x: 7.5, y: -2.8 }, { x: -7.5, y: -2.8 }] },
  ...
]
```

- `pts` 是**机体系俯视坐标**（机头 +y，右翼 +x，单位米）
- **`pts` 同时就是俯视识别图的标注锚点** —— 单一数据源，不要再另建一份
- 每组点数**必须是偶数**（成对挂载），所以齐射数总是偶数

### 挂载点类型

| kind | 位置 | 能挂什么 |
|---|---|---|
| `tip` | 翼尖 | 只受得起轻型空空弹 |
| `light` | 通用挂架 | 中型弹、吊舱 |
| `heavy` | 重挂点 | 大型弹只有这里挂得下 |
| `belly` | 机腹 | 吊舱与对地弹 |

### 武器挂载属性 `STORE_ATTR`

```js
srm: { fits: ['tip', 'light', 'heavy'], perPoint: 4, mass: 95 }
```

| 字段 | 含义 |
|---|---|
| `fits` | 能挂的挂点类型 |
| `perPoint` | **单个挂载点**提供几发 |
| `mass` | 单件重量（kg） |

**为什么单独放一张 `STORE_ATTR` 表而不是塞进 `WEAPONS`**：
这样能横着比较"谁挂得下、谁带得多、谁更重"，不用在几百行表里翻。

下游专用弹（DAR-4 / BIN-6 / BAD-9）的 `fits` 是**空数组**，
表示玩家挂不上它们。

## 配置与派生

机库里改的是：

```js
loadouts[机型 id] = { A: 'srm', B: 'v11', C: null, D: null }
```

出击时 `resolveLoadout()` 派生出：

```js
player.loadoutList = [
  { wid, w, points: 4, ammo: 8, salvo: 4 },
  ...
]
player.ammoPool = { srm: 8, v11: 4 }
player.wpIdx = 0                    // 当前选中哪一条
```

同一种武器占多个组 → **合并成一条**：弹药累加，`salvo` 累加。

`syncWeapon(a)` 把 `wpIdx` 同步到 `special` / `spAmmo` / `spSalvo`——
这三个字段是给既有代码路径用的，`launch()` 直接读它们。

## 发射与装填

**一个挂载点 = 一个发射槽。** 按一次发射键打 **1 枚**，
占用一个冷却完毕的槽：

```js
// 找一个空闲槽
for (i = 0; i < slotArr.length; i++) {
  if (slotArr[i] <= 0) { slotIdx = i; break; }
}
if (slotIdx < 0) return false;      // 全在装填，按不出去
...
slotArr[slotIdx] = wp.cd;           // 只有这个槽开始计时，其余不受影响
```

所以「齐射数」（`points`）的真正含义是：

> **能一口气连打几发**，不是"一次打出几发"。
> 每个槽的冷却**各自计算** —— 连打两发之后，
> 第一发先装填好，第二发稍后。

**为什么这样更好**：它让"挂多个挂载点"的收益变成
「更大的瞬时爆发 + 更快的持续输出」，而不是"一次多打几枚"。
前者更接近真实挂载的战术价值，也让发射节奏成为玩家能经营的东西。

`spCd` 取**最快就绪的那个槽**的剩余时间，
只是给 HUD 与 AI 一个"现在能不能打"的判据，不参与实际计时。

**注意 `STORE_COOLDOWN` 必须覆盖所有可发射武器**（`smoke.js` 会检查）。
漏掉的话那件武器会保留 `data.js` 里的原始 `cd` ——
那个值可能是按旧语义定的，会快得离谱（CLA-17 就这样漏过一次）。

## 被动吊舱

`STORE_ATTR` 里有 5 件 `passive: true` 的吊舱。它们**不占扳机**——
装上就一直在起作用，也不会出现在 HUD 的武器纵列表里。

| 字段 | 效果 |
|---|---|
| `lockResist` | 敌方对你的锁定距离 ×(1−x) |
| `armorBonus` | 全向减伤（可叠加，上限 55%） |
| `lockRangeBonus` | 你的锁定距离 ×(1+x) |
| `flareBonus` | 额外干扰弹组数（乘挂载点数） |

汇总由 `passiveEffects(ac, lo)` 完成，在 `startMission()` 里落到
`p.armor` / `p.lockResist` / `p.lockRangeK` / `p.flares` 上。

**为什么要有被动挂载**：它们让"少带一枚弹"变成真实的取舍，
而不是纯损失。带满弹的飞机更重更笨，而一件吊舱换来的可能是
整场交战的锁定优势，或者一次活下来的机会。

**两条路径不要混**：`resolveLoadout()` 会 `continue` 掉 `passive` 武器
（它们没有扳机可扣），被动效果必须走 `passiveEffects()` 单独汇总。

## 重量惩罚

```js
lf = min(1, 总挂载重量 / maxLoad)      // loadFactor
lp = loadoutPenalty(lf)                // data.js —— 全项目唯一一份

vMax   × lp.vMax      // 1 − 0.08·lf
vMil   × lp.vMil      // 1 − 0.06·lf
vStall × lp.vStall    // 1 + 0.05·lf（挂载让它更高）
acc    × lp.acc       // 1 − 0.26·lf  ← 最重的一项
pitch  × lp.pitch     // 1 − 0.18·lf
roll   × lp.roll      // 1 − 0.12·lf
```

在 `stepAircraft()` 里对机型物理数据做临时缩放。

**AI 不带挂载，`loadFactor` 是 `undefined`**，所以这些惩罚只作用于玩家。

这是"空置挂架换机动性"的实现方式，也是半拟真感的来源之一 ——
满载出击真的会飞得笨。

### 系数只有一份

`loadoutPenalty()` 放在 `data.js`，**机库面板和物理共用它**。

原因是一次真实的漂移：面板曾经自己写了一个 `loadK × 18`，
只取了俯仰那一项，把最狠的加速 −26% 和失速速度升高全漏掉了，
玩家看到的损失比真实手感小得多。两处各写一套数字迟早会对不上，
而且对不上的时候很难发现。

同理，面板上出现过的 `−0%` 也是这套漂移的产物：
判断阈值用 `loadK > 1%`，显示却用 `loadK × 18`，
于是 `loadK` 在 1%–2.8% 之间时会走进"有惩罚"分支却算出 0。
现在小于 1% 一律显示 `<1`。

### 机体能力门槛

**两层筛选是独立的**，缺一不可：

| 层 | 字段 | 判据 | 回答的问题 |
|---|---|---|---|
| 挂点类型 | `WEAPONS[].fits` | 是否包含该组的 `kind` | **物理上挂不挂得住** |
| 机体能力 | `WEAPONS[].needs` ∩ `AIRCRAFT[].caps` | 机型是否具备所需能力 | **这架飞机撑不撑得住** |

只有 `fits` 的时候，"位置一样就能挂" —— 于是制空战斗机也能挂上
重型巡航导弹，机体差异等于白设计。所以补了第二层。

**限制只加在少数武器上**，大部分弹谁都能挂：

| 能力 | 含义 | 需要的武器 |
|---|---|---|
| `strike` | 对地 / 对海打击（完整对地火控与重型挂架） | 反辐射、加固侵彻、防区外对地、远程巡航、反浮空平台、反大型 |
| `intercept` | 高空高速拦截（高空点火与冷却） | 极高空拦截弹、超远距空空弹 |
| `ew` | 电子战（供电与散热） | 主动电子战吊舱、定向能 |

机型的 `caps`：

| 机型 | caps |
|---|---|
| DB-11 军舰鸟 | `strike` `ew` |
| D-14 旗鱼 | `intercept` |
| G-6 鲣鸟 | `strike` |
| F-9 海燕 | `intercept` |
| D-21 贼鸥 | `strike` `ew` |
| D-33 信天翁 | （无）—— 纯格斗机，20 种通用弹 |

判定函数是 `canCarry(ac, w)`。**默认配置也受这条约束**，
`preflight` 会检查，`smoke.js` 也会。

界面上，机库的选装面板会提示有多少项因能力不足被挡掉
（`· N 项因机体能力不足不可挂`），免得玩家以为是 bug。

## 界面怎么表达

机库的六维条显示的是**挂载之后**的实际值：

```
机动性   ████████████░░░░  68  −16
         └─实际值──┘└损失┘
```

- 实心条 = 挂载后的实际值
- 紧跟其后的暗红段 = 被挂载吃掉的部分
- 右侧 `−16` 是净损失

**只有受挂载影响的维度会缩水**：

| 维度 | 受挂载影响 | 算法 |
|---|---|---|
| 最大速度 | ✅ | `× lp.vMax` |
| 机动性 | ✅ | `× (lp.pitch + lp.roll + lp.acc) / 3` |
| 低可探测 / 火力 / 生存性 / 航程 | ❌ | 机型固有值 |

下方「出击配置」里另有**逐项明细**（加速 / 俯仰 / 滚转 / 最大速度 / 失速）——
合成成一个"机动性"数字会掩盖"加速掉了 26%"这种关键信息，
而那恰恰是手感上最先感觉到的。

## 界面

### 机库

选装是一个**两栏面板**，不是下拉框：

| 栏 | 内容 |
|---|---|
| **左** | 挂载点组列表：组号、位置、点数与类型、当前挂了什么。点击切换右栏 |
| **右** | 当前组能挂的东西，**每个一张卡片**：型号 + 中文名 + 携弹量、**定位**、**简介**、关键参数（射程 / 导引 / 重量 / 冷却） |

**右栏只列出 `fits` 包含该组类型的武器**——这就是出装限制的体现。
「空置」排在最前面，因为它是一个正经选项而不是"什么都不选"。

**为什么不用下拉框**：早期版本是 `<select>`，里面只有型号
（`TOR-2 ×16`）。玩家根本不知道 TOR-2 是什么——打什么的、能打多远、
为什么该选它而不是旁边那个，全都得靠背。
卡片把**定位**（一句话说清战场角色）和**简介**直接摆出来，
和机库里选机体时的信息密度对齐。

相关函数：`buildHpGroups()`（左）、`buildHpPicker()`（右）、
`makeStoreCard()`（单张卡片）、`storeStatLine()`（卡片底部参数行）。

### 游戏内

HUD 底部中央是武器纵列表：

```
      > TOR-2    16  ●○
        GIR-9     4  ●
```

- 当前项左边有 `>`，用琥珀色
- 数字是余弹
- **`●` = 该槽就绪，`○` = 装填中** —— 全部空心就是按不出去
- 余弹归零转红

`R` 键循环切换（`cycleSpecial()`）。**只有一种武器时它会静默返回。**

### 缩略图

每组从挂载点引一条折线到左右两侧的标注栏（偶数索引标右、奇数标左——
全堆一侧会四线交叉穿过机身），线上方写 `GROUP A`，下方写型号与总数。

## 加一种新武器

1. 在 `WEAPONS` 里加数据
2. 在 `STORE_ATTR` 里加 `fits` / `perPoint` / `mass`
3. 需要的话加进某个机型的 `defaultLoadout`
4. 跑 `node tools/smoke.js`

**别忘第 2 步。** 漏了不会崩，但那个武器永远不会出现在任何下拉框里。

## 加一架新飞机

1. 在 `AIRCRAFT` 里定义 `hardpointGroups`（**点数必须成对**）和 `defaultLoadout`
2. 在 `planform.js` 的 `P` 里加同名的俯视轮廓
3. 跑冒烟测试

`preflight()` 会检查：组是否成对、每组是否有武器挂得上、
默认配置里引用的武器是否真的能挂到那一组。
