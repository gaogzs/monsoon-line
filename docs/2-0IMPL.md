# 2.0 实施计划

对应 [2-0PLAN.md](2-0PLAN.md)。本文是落地方案：分阶段、每阶段独立发布、每步都能玩能验。数值都是**起步值**，以各阶段的探针脚本实测为准再调。

已定的决策：
- 版本号计划（2026-10-19 重排）：
  - **v1.12** 机炮抗性（已发）
  - **v1.13** 范围伤害与近炸引信（已发，含 1.13.1 电子战压制、1.13.2 HUD 滤镜与航线修复）
  - **v2.0.0** 阶段 2.5：后台模拟框架 + WebGL 渲染。换引擎是架构层面的变化，所以算主版本（已发）
  - **v2.0.1** 分段航线与有效射程、锁定改动（计划外，已发）
  - **v2.1.0** 2.5.9 画面升级：天空、海面、平面云层、粒子进 WebGL（云团封存，见 rendering.md）
  - **v2.2** 阶段 3：旋转炮塔与多炮塔
  - **v2.3** 阶段 4：舰对舰、近防拦截、舰船尾部水花、海上平台、新关卡
  - **v2.4** 阶段 5：炮弹与导弹的高度相关物理重构
  - 之后的更新都在 2.x 上往后数。
- 近防炮拦截用**混合方案**：按概率判定，炮塔真实转向并打出曳光"配合演出"。只有炮管已经对准导弹、真正开火之后才开始定时掷骰。
- 动能杀伤弹**只在设定上是动能**。伤害固定，不按相对速度计算。

## 阶段 1 · v1.12 机炮抗性

### 1.1 基础设施
> **已实施（v1.12）**：机炮抗性只在 `scanShot` 一处结算，落成 `Ent.gunResistK`（entities.js），没有提前建 `combat.js`。伤害收口和 `js/combat.js` 挪到阶段 2，和 blast 一起做。

1. 新建 **`js/combat.js`**（在 entities 之后、game 之前加载），收口伤害：
   ```js
   // info: { kind:'gun'|'blast'|'direct', w: weaponDef|null }
   Combat.apply(ent, amt, world, source, info)
     → amt *= Combat.resistK(ent, info)   // 机炮抗性
     → ent.kind==='target' ? hitTarget路径 : Ent.damage路径（JDA-3 armor 仍在 Ent.damage 内另乘）
   Combat.resistK(ent, info) = (info.kind==='gun' && info.w && info.w.cal <= SMALL_CAL) ? 1 - ent.gunResist : 1
   ```
   常量 `SMALL_CAL = 40`（mm）。75mm 以上舰炮不吃机炮抗性。
2. 所有机炮武器加 `cal` 字段：k3/k1/k2 = 20，k7/k11 = 30。
3. `fireGun` 生成子弹时带上 `w` 和 `cal`（`entities.js:1683`）。
4. `scanShot`（`game.js:2387/2418`）、`hitAny`、`detonate`、`clusterBurst` 都改为调用 `Combat.apply`。`bombTheBase`（`missions.js:179`）用 `kind:'direct'`。
5. 字段 `gunResist ∈ [0, 0.999]`：
   - 飞机写在 `AIRCRAFT[].phys.gunResist`，由 `makeAircraft` / `spawnEnemy` 复制。
   - 舰船写在 `SHIPS[].gunResist`，由 `spawnShip` 复制。
   - 地面设施在 `spawnTarget` 调用处传入。
   - 调节单元在 `spawnCellField` 里设置。
   - 缺省为 0。

## 阶段 2 · v1.13 范围伤害与近炸引信

### 2.1 新字段（替代旧 `prox`）
| 字段 | 含义 |
|---|---|
| `fuze` | 近炸触发半径（m，测到目标表面）。0 / 缺省 = 只有直接碰撞才起爆 |
| `blast` | 爆炸半径（m，测到受害者表面）。0 = 无溅射，只伤害直接命中的目标 |
| `blastCore` | 满伤半径（m） |
| `blastAir` | 默认 true。false = 只伤地表（子母弹） |

衰减：令 `d = max(0, 距离 − 受害者半径)`。
```
d <= core       → k = 1
core < d < R    → x = (d−core)/(R−core);  k = (1−x)²      // 二次衰减：破片密度和能量同时下降
d >= R          → k = 0
```
受害者半径：飞机统一用 `HIT_R_AIR = 7.5`（与 scanShot 一致，做成常量），地表目标用 `tg.radius`。

### 2.2 机制
1. **`Combat.blast(world, pos, w, source)`**：遍历 `actors` 和 `targets`，跳过 `team === source.team`（与子弹的 `team !==` 规则一致，中立单位照样会被炸到）和发射者本人。每个受害者的伤害为 `dmg × k × warheadK × antiRadar`，类型 `kind:'blast'`，不吃机炮抗性。直接命中的目标 `k` 取 1。
2. **近炸：在最近的那一刻起爆**
   - 每帧对导弹和目标的相对运动做线段最近点计算，避免 700 m/s 时每帧 12 m 的穿越漏判。本帧最近距离 < `fuze`，并且最近点落在本帧内（相对距离由减转增），就在最近点起爆。
   - 直接撞上（与目标表面的距离 < 1.5 m）当帧起爆，按满伤处理。
   - 只检测导弹自己的目标（或下面第 3 条的诱饵），沿用现状，不对路过的其他飞机触发。爆炸伤害本身会波及附近所有人。
   - **不做任何人为偏移**：制导照常瞄准目标，该正中就正中，打不机动的目标时直接命中满伤是对的。伤害的分布来自真实的脱靶因素：
     - 目标机动，导弹转向率和速度跟不上（现有的 `turnFactor`、转弯掉速）；
     - 一阶提前量（`w.lead`）对加速或转弯中的目标有误差；
     - 导引头视场丢失、诱饵、重捕获造成的末段扰动。
     机动越狠，脱靶越远，伤害越低。这正是"擦肩而过不够、要真正甩开"的体验来源。
   - 验收：probe-blast 按目标机动档统计"起爆距离 / 爆炸半径"的直方图。
     - 不机动：以直接命中为主。
     - 一般机动和急转：比值要有明显分布，标准差 ≥ 0.15 × blast，并且随机动强度变大，平均伤害单调下降。
     - 如果急转档的分布仍然太集中，说明近炸半径相对导弹的跟踪误差太大，调 `fuze` / `blast` 的比例，不加偏移。
3. **打上干扰弹也会正常爆炸**：现在被热焰弹或箔条骗走的导弹只是 `target = null` 盲飞，到寿命结束都不会炸（`entities.md:377`），干扰弹云只用于后面的重捕获判定（`decoyRecheck`）。改成：
   - 被骗时 `breakLock` 已经记下了 `m.decoy`（位置 `p`、速度 `v`、起始时刻 `t0`）。在盲飞期（`reLockT > 0`）内，导弹把 `decoy` 当前的外推位置 `p + v × (age − t0)` 当作虚拟目标继续制导，转向和速度损失照常计算，而不是直飞。
   - 对虚拟目标也做第 2 条的最近点近炸。诱饵视为半径 4 m 的球，触发半径同样是 `fuze`，在离诱饵最近的那一刻起爆，然后调用 `Combat.blast`。
   - 后果是爆炸会波及附近的人。干扰弹投得太晚，诱饵还在机身旁边，导弹在诱饵上炸开照样会溅到自己。这让"什么时候投弹"有了分量：提前投可以完全躲开，贴脸才投就是赌。
   - 诱饵熄灭（超过 `DECOY_LIFE`），或者盲飞期内重新咬住真目标（`decoyRecheck` / 重捕获），就切回真目标或恢复搜索，不再追诱饵。
   - 电子干扰（`openEcm`）这类没有实体诱饵的欺骗不变：导弹盲飞，寿命结束时在空中自爆（第 4 条）。
   - 验收：probe-blast 增加一组"投弹时机"实验，热焰弹分别在距离 3 km、1 km、300 m、100 m 时投放，统计投弹机受到的平均伤害。期望早投接近 0、贴脸投明显大于 0，并且曲线单调。
4. 撞地 / 撞海、寿命结束（包括电子干扰后盲飞到期），都调用 `Combat.blast`。现在这些情况是哑弹（`entities.md:377`）。
5. `clusterBurst` 删掉，改为 `blast = cluster`、`blastCore = cluster`（平伤）、`blastAir = false`。
6. 非制导火箭和炸弹走 `scanShot` 命中或撞地，再调用 `Combat.blast`，没有 `fuze`。
7. 玩家处于爆炸半径内受伤时：屏幕抖动 + 受伤闪烁（已有受伤反馈的话复用）。

### 2.6 爆炸特效与伤害范围同步
现在所有弹头起爆都调用同一个 `explode(list, pos, scale, count)`（`entities.js:1805`），scale 基本写死为 1.0 到 1.4。画面上爆炸多大，和伤害打多远没有关系。改完以后，玩家应该能从画面上读出"这一发炸多大"。画面不必和数值完全一致，但要成比例。

1. **新函数 `Ent.blastFx(world, pos, w, opts)`**，放在 `combat.js`。`Combat.blast` 起爆时调用它，原来直接调 `explode` 的起爆点（`detonate`、撞地、`clusterBurst` 的替代）也统一改调它。尺寸全部从武器的 `blast` / `blastCore` 推出来，不需要逐个武器配置特效。
2. **火球（偏小）**：目视半径 `ballR = clamp(0.35 × blast, blastCore, 0.5 × blast)`，并且不小于 4 m。
   - 现在 scale 1 的火球大约扩散 26 m（粒子初速最高 58 m/s，按 `stepParticles` 的阻力 2.2 反算），所以换算成 `scale = ballR / 26`。
   - 粒子数 `count ∝ √scale`，在 10 到 28 之间夹紧。
   - 火球故意比伤害范围小：中心那团火是"满伤区"的提示，外围靠破片表现。
3. **破片壳（球形扩散）**：一圈小而亮的粒子从爆心均匀地向外飞，飞到 `blast` 附近消失。
   - 方向用 Fibonacci 球面分布加小抖动，比纯随机更像一个均匀膨胀的球壳，也不会出现明显空洞。
   - 初速和寿命按阻力模型反算，让最远飞行距离约等于 `blast`：线性阻力下最远距离 = `v0 / drag`，所以取 `v0 = blast × dragFrag`。`dragFrag` 取 3–4，破片会先快后慢，最后停在半径附近。寿命取到速度衰减到约 10% 为止。
   - 外观：0.5–1.2 m 的亮点，颜色从 `#fff2c0` 渐变到灰色，不膨胀（`grow:false`），不受重力，或只受很小的重力。如果渲染器支持按速度拉长成短线，就画成短线，看起来更像破片。
   - 数量按 blast 档位：格斗弹 24，中距弹 36，重型弹和中距重战斗部弹 56，对地重弹 40。
   - 破片壳叠加 30% 的弹体速度，这样高速掠过时的爆炸是一个被拖长的椭球，比原地停住的球自然。
4. **按弹种区分**：
   - 空空弹：完整球壳。
   - 对地 / 反舰弹撞地或落水：只取上半球的方向（半球壳），再加一点尘土或水花粒子。落水时加一根竖直水柱，高度约 0.6 × blast。
   - 子母弹（`blastAir:false`、平伤）：不画一个大球。在 cluster 半径内随机撒 6–10 个小爆点，每个用小火球加少量破片，起爆时间在 0–0.3 s 内错开，看起来像一片子弹药依次炸开。
   - 动能杀伤弹（`blast 0`）：没有火球和破片壳。命中时画一个短促的白闪加少量碎屑火花；没命中就什么都没有。
   - 大口径炮弹空爆（阶段 3）：沿用同一个函数，按 n50 / n75 / n120 的 blast 自动缩放，对空射击时天上出现一团团大小不一的烟团。
5. **烟团**：保留现在的深灰烟团，大小跟着 `ballR` 走，停留时间稍长，用来事后标记"刚才在这里炸过"。
6. **预算和细节等级（LOD）**：
   - 粒子总上限仍是 900（`compact`）。
   - `blastFx` 先看当前粒子数：超过 650 时破片数减半，超过 800 时只画火球。
   - 距相机超过 6 km 时破片数减半，超过 12 km 时不画破片。
   - 齐射（比如 8 枚同时起爆）不能挤掉玩家身边正在发生的爆炸。
7. **玩家视角**：玩家在 blast 范围内时，破片会从机身旁飞过，配合 2.2 节第 7 条的屏幕抖动，玩家能感觉到"这一下擦到了"。
8. **可调参数**：`BLAST_FX = { ballK:0.35, ballMaxK:0.5, fragDrag:3.5, fragN:{…}, lod:{…} }` 集中放在 `combat.js` 顶部。个别武器需要特殊外观时，可以在武器数据里写 `fx:{ ballK, fragN }` 覆盖，但默认不写。
9. **验证**：
   - smoke：用 `stepParticles` 把一次 `blastFx` 推进到结束，统计破片最远飞行距离，应在 [0.8, 1.15] × blast 之间；火球粒子最远距离应 ≤ 0.55 × blast。8 发齐射时粒子总数不超过上限，并且 LOD 生效。
   - 手动：格斗弹、中距弹、重型弹、子母弹、落水各截一张图，对比三档空空弹的球壳大小，确认能一眼区分。

### 2.7 展示与验证
- 挂载图鉴 inv2 加"引信 / 爆炸半径"两列，`weaponParams` 加同名两行。检查 desc 里引用 `{{prox}}` 的模板并替换。

## 阶段 2.5 · v2.0.0 后台模拟框架与 WebGL 渲染

换渲染引擎是架构层面的变化，完成后发 **v2.0.0**。之后的阶段都在 2.x 上往后数。

先做模拟框架（2.5.1），再做 WebGL 迁移（2.5.2–2.5.6）。理由是迁移期间要靠模拟框架确认"游戏逻辑一点没变"，阶段 3、4 的 `probe-turret` / `probe-ciws` 也直接建在它上面。两件事一起发版。

### 2.5.1 后台模拟框架 `tools/lib/sim.js`

**现状**
- `smoke.js`、`probe-missions.js`、`probe-blast.js` 各自抄了一份沙箱：假 DOM、假画布、假 `requestAnimationFrame`、手动推帧，细节还不一样。
- 游戏里大量用 `Math.random`，没有统一种子，同一场模拟每次结果不同。只有 `probe-blast` 自己替换了随机数。
- 主循环靠假 `requestAnimationFrame` 一帧帧推，HUD 绘制也照跑。

**要做的**
1. **统一沙箱**：`Sim.load()` 按 `index.html` 的顺序加载全部脚本，渲染器、HUD、HudFx、音效换成空实现。smoke 和所有 probe 改用它。
2. **固定种子**：`Sim.seed(n)` 替换全局 `Math.random`。同一个种子跑出同一场战斗，用来复现 bug、对比改动前后。
3. **直接步进**：`Sim.step(dt)` 只推进游戏逻辑（`game.js` 的逻辑帧），不走 `requestAnimationFrame`、不画 HUD。需要从 `game.js` 导出一个"只跑逻辑"的入口，和现在的 `__updateTargets` 等测试钩子放在一起。
4. **场景脚本**：一个场景就是一个函数，可以开某一关，也可以自己摆单位。例如：
   - 开第 3 关、玩家无敌、每秒朝干扰机飞；
   - 两支舰队对射。

   框架负责跑、计时、收集记录。
5. **批量统计**：同一场景换 N 个种子跑，输出平均值、分布、最坏情况。

**第一批场景（同时用来回归 v1.13.2 的航线修复）**
- m2：基地被轰炸机炸到失守要多久（玩家不作为 / 只打护航 / 优先打轰炸机三种策略）。
- m5 / m8：反舰弹真的放出来以后，我方资产的损失分布。
- m3 / m5 / m7：干扰机开机次数、玩家处在压制场里的时间占比。

**验收**
- smoke 和全部 probe 改用 `Sim` 之后结果不变。
- 同一种子连跑两次，逐帧状态完全一致。
- 一关 150 s 的模拟，在 Node 里跑完不超过现在 probe-missions 单关耗时的一半。

### 2.5.2 渲染接口

把游戏代码对画布的直接调用全部收进一层接口。以后游戏代码只调这层，不碰画布。

| 接口 | 用途 |
|---|---|
| `setCamera(pos, fwd, up, fov)` | 相机 |
| `begin()` / `pushModel(model, pos, fwd, up, opts)` / `flush()` / `end()` | 模型 |
| `drawParticles(list)` | 粒子（含 `streak`、`delay`，见 v1.13） |
| `drawSky()` / `drawSea()` / `drawClouds()` | 环境 |
| `ctx2d()` | 叠在 3D 上面的 2D 画布：HUD、HudFx、屏外标记都画在这层 |

实现有三个：
- **WebGL**：浏览器里的默认实现。
- **2D**：现在的 `render.js`，作为回退。WebGL 不可用时用它，离线出图工具也用它。
- **Null**：空实现，给模拟框架用。

### 2.5.3 着色规则只写一份

新文件 `js/shading.js`，集中放这些东西：
- 光照方向、亮度公式（`0.44 + 0.56 × |n·L|`、双面取绝对值）；
- 雾的颜色和距离（`FOG_NEAR` / `FOG_FAR` / `FOG_MAX`）；
- 亮度和雾的量化档数（现在各 16 档）；
- `tint` / `emissive` / `alpha` 的含义。

WebGL 着色器里的常量由它生成，2D 回退也读它，改一处两边一起变。

**刻意保留现在的画风**：
- WebGL 也是每个面一个颜色（平涂），不做平滑光照。
- 雾按每个面的平均深度算，和现在一样，不改成逐像素。
- 不加纹理、不加阴影。画面升级以后另起一个版本做，不和迁移混在一起。

### 2.5.4 WebGL 实现（`js/render-gl.js`）

- **手写 WebGL，不引入 three.js**：保持静态托管、双击 `index.html` 能玩、不带第三方库。
- **模型**：`models.js` 的数据第一次用到时转成顶点缓冲，每个面展开成三角形，带面颜色和法线；之后每帧只传变换矩阵。可变后掠翼（`sweep` / `morph`）每帧更新那几个顶点。
- **深度缓冲**：开启。背面剔除沿用 `face.cl` 标记：闭合部件剔除，单片翼面双面。
- **粒子**：一个动态缓冲批量画。`lighter` 叠加混合对应 `gl.blendFunc(ONE, ONE)`；`streak` 用短线段或拉长的四边形。
- **透明面**（`alpha < 1`）：不透明面先画，透明面按深度排序后画，关闭深度写入。
- **2D 叠加层**：一块和 3D 同尺寸、背景透明的 2D 画布叠在上面。HUD、HudFx、文字都留在 2D，不进 WebGL。
- **回退**：`getContext('webgl')` 失败时自动换成 2D 实现。设置里加一个"渲染：自动 / WebGL / 兼容（2D）"选项。

### 2.5.5 所有 3D 界面共用同一个渲染器

- 现在单位详情页的 3D 预览（`unitview.js` 的 `renderModel`）是另一套独立实现：自己投影、排序、上色。迁移时删掉，改为调用同一套渲染接口，只传自己的相机和画布。
- 以后新加的 3D 界面（机库预览等）一律走这套接口，不再各写一份。
- 离线出图工具（`render-mounts`、`render-ships`、`render-units`）用 2D 实现加 `tools/lib/raster`，和现在一样不需要浏览器。

### 2.5.6 画面对比测试（新工具 `tools/probe-render.js`）

**固定场景**
- 每个机型、每艘舰船各一张，固定角度；
- 挂满弹的机翼特写，从上方和下方各一张，专门看挂弹遮挡；
- 远处带雾的编队；
- 粒子：一次中距弹爆炸、一次子母弹落地。

**比对方式**
- 每个场景分别用 WebGL（无头浏览器截图）和 2D（`tools/lib/raster`）出图，逐像素比较。
- 差异超过阈值就报错。
- 遮挡区域在 2D 里本来就会排错，这部分用遮罩排除，或者放宽容差。
- 用 WebGL 的那半边需要无头浏览器。它只在本地手动跑，不进 smoke。smoke 继续只用 Null 实现，不依赖浏览器。

### 2.5.7 验收
- 挂弹遮挡：从上往下看，翼下挂弹被机翼挡住；从下往上看，挂弹盖在机翼前面。机身和尾翼穿插也都正确。
- 画面对比测试全部在阈值内。并排截图对比，配色和雾的观感一致。
- 帧率：最重的场景（m8 舰队防御、sk1 第四周）不低于现在，目标是明显更高。
- smoke、probe-missions、probe-blast 全绿，并且已经改用 `Sim`；离线出图工具照常能跑。
- 强制使用 2D 回退时，游戏能完整打通一关。
- 文档：`docs/systems/rendering.md` 重写；`tools.md` 补 `Sim` 和 `probe-render`；`unitview.md` 同步。

### 2.5.8 风险
| 风险 | 缓解 |
|---|---|
| 画风变了，玩家觉得"不像原来的游戏" | 着色规则只写一份、画面对比测试兜底；平涂和逐面雾原样保留 |
| 2D 和 WebGL 两套实现慢慢走样 | 同一层接口、同一份着色规则；新功能只写接口调用，`probe-render` 定期跑 |
| 低端集成显卡或远程桌面退回软件 WebGL，反而更慢 | 设置里可以手动选"兼容（2D）"；检测到软件渲染时提示 |
| 迁移期间逻辑被意外改动 | 先完成 `Sim`；迁移前后用同一组种子跑场景，逐帧状态必须一致 |

### 2.5.9 迁移之后的画面升级（记录在案，迁移验收完再一起做）

迁移本身刻意不改画风（见 2.5.3）。下面这些等 v2.0.0 验收通过后单独做，可以合成一个版本，也可以拆成几个小版本。前提是都建在 WebGL 渲染上；2D 回退保持现在的样子，不追这些效果。

**1. 云层（方案 A + C）**
- **现状的问题**：每朵云是 2D 画布上叠的几个半透明椭圆。云与云之间没有遮挡，也不会被飞机挡住（永远画在模型后面），近看就是一堆平面椭圆。
- **A · 柔边云团**：
  - 每朵云由 5–12 个大的柔边贴片组成。贴片纹理在运行时用噪声生成，不需要美术资源。
  - 顶部受光偏白、底部压暗；远处融进雾里。
  - 参与深度测试：飞机能钻进、钻出云。贴片之间按距离排序，用软粒子（靠近模型表面时淡出），免得出现硬切边。
  - 沿用现在五层高度的分布（500 – 21 400 m），保证每个飞行高度附近都有云当姿态参照。
- **C · 高空云层**：10 km 以上加一到两层带噪声纹理的薄云片（卷云、层云），随距离淡出。高空关卡（第 3 关这类）的天空不再是空的。
- **不做**：光线步进的体积云（方案 B）。太吃显卡，在两万米这种稀薄高度效果也有限。以后真要做画面大升级再议。

**2. 海面实体化**
- **现状的问题**：海面是按"海天分割线"算出一条线，下面填渐变色，再画一张 500 m 的网格线。方向感和速度感主要靠那张网格，低空时缺少参照，高空时又只剩一片色块。
- **做法**：
  - 海面是一张跟着相机移动的大网格，近处密、远处疏，按地球曲率往下弯（现在的地平线俯角计算保留，改成几何上真的弯下去）。
  - 逐像素雾，一直融到地平线。
  - 程序生成的波浪法线（不必真的动顶点）。太阳方向的高光反射（太阳闪烁带）随机头朝向移动，提供方向感。
  - 低空时能看清波纹、白浪，速度感来自海面纹理的流动；高空时纹理自然糊成一片，但高光带和雾的层次还在。
- **以后**：分水群岛的岛屿、礁石作为地形网格加进来（设定里本来就有群岛），给低空关卡提供真正的地标。等关卡需要时再做。

**3. 天空**
- 天空渐变和太阳光晕改成 WebGL 里的天空穹顶：按视线方向逐像素算渐变，太阳周围加大气散射的光晕。
- 和云层、海面用同一套雾和光照参数（`shading.js` 扩展）。

**4. 粒子进 WebGL**
- 爆炸、破片、尾迹、曳光批量画，并参与深度测试：飞机背后的爆炸会被机身挡住。现在粒子永远画在模型上面。
- 破片的 `streak`、子母弹的 `delay` 等行为不变。

**验收**
- 每一项单独开关，做完一项就和旧画面并排对比。
- 帧率：最重的场景不能比 v2.0.0 掉 10% 以上。集成显卡上提供一个"画面：标准 / 高"的开关，"标准"关掉软粒子和高空云层。
- `probe-render` 加上云层、海面的场景截图（这些只看截图，不做 2D 对比）。

## 阶段 3 · v2.2 旋转炮塔与多炮塔

> **已完成**（细节见 [systems/turret.md](systems/turret.md)）。与下面原计划的出入：
> - 伤害保持原表，平衡改用射速、散布和迟钝的火控：
>   - 射速：近防炮 1800 → 450，尾炮和 30 mm 遥控炮更慢（300），50 / 75 / 120 mm 只略降。
>   - 散布：中大口径对空散布很大，对海面另算（`spreadSurface`）。
>   - 火控：提前量迟钝。
>   - 效果：平直贴近 Dunkleosteus 必死（约 190 hp），2 g 机动约 50，6 g 机动约 0。
> - 命中率探针仍在 1.2 km 测（探针里去掉 airRange），期望区间随削弱下调（直线 20–45%、急机动 ≤ 7%）。提前量多了一个只信 15% 的加速度估计，转动加了前馈。
> - 50 mm 也打海面目标（`surface: true`）。炮塔也能装导弹发射架（`kind: 'launcher'`），目前没有舰船用。
> - 顺带：船体 V 形底、悬空零件向下延长、桅杆挪到舰桥顶、斜置弹箱不再被舰桥挡住、座头鲸甲板飞机修正、远处模型随地球曲率下沉。

### 3.1 前置重构
- `Ent.fireGunFrom(shooter, w, muzzlePos, dir, world)` 作为生成子弹的核心。`fireGun(a, world)` 改为用机头位置和 `a.fwd` 调用它，行为不变。
- 子弹支持 `gravity`（倍率）、`fuze`、`blast`、`cal`、`w`，供大口径炮弹使用。
- 只有带 `fuze` 的炮弹才对 actors 做近炸检测，开销可控。

### 3.2 数据结构（新文件 `js/turret.js`，数据放 `data.js` 的 `TURRET_GUNS`）
挂在单位定义上：`SHIPS[].mounts` / `AIRCRAFT[].mounts`。
```js
mounts: [{
  id: 'ciwsF', gun: 'ciws20',
  pos: [0, 9.2, 52],            // 模型空间：船头 +z，右舷 +x，上 +y，单位 m
  yaw0: 0,                      // 零位朝向（弧度，相对船头）
  arc: { yawMin:-2.6, yawMax:2.6, pitchMin:-0.1, pitchMax:1.45 },
  slew: { yaw:1.6, pitch:1.2, accel:3.0 },    // 最大角速度 rad/s、角加速度 rad/s²
  model: null | 'tur75',  barrel: 4.2,         // 有实体时炮弹从炮口射出
  role: 'aa' | 'surface' | 'dual' | 'ciws',
  aim: { err: 0.004, lag: 0.5, react: 0.6 }   // 瞄准噪声σ、速度滤波时间常数、索敌反应时间
}]
```
运行时状态 `{ yaw, pitch, wYaw, wPitch, target, scanT, cd, ammo, vEst, noise }`，在 `makeTarget` / `makeAircraft` 里由 `Turret.make` 生成，挂到 `ent.turrets`。

### 3.3 每帧逻辑 `Turret.step(tu, host, world, dt)`
1. **索敌**：每 `react` 秒一次，带抖动错开。在射程 + 余量内、射界内、按 role 过滤的敌对单位中，按"转到目标所需时间 + 距离权重"打分，选最低者。当前目标仍有效时保留（滞回）。
2. **提前量**：
   - 不读目标真实速度，而用滤波速度 `vEst += (t.vel − vEst) × dt/lag`。这一项天然产生迟钝：匀速平飞时 `vEst` 收敛，必中；缓慢转弯或加速时滤波滞后加上纯直线外推，有小偏差；乱机动时 `vEst` 总是落后，基本打不中。
   - 拦截点用 2 次迭代：`tof = dist/v_shell`，`aim = t.pos + vEst×tof`，再加炮弹下坠补偿 `+½ g·gravity·tof²`。
   - 瞄准噪声：OU 过程（均值回归的平滑随机游走）叠加在瞄准方向上，σ = `aim.err`，让误差是缓慢漂移而不是逐发跳动。
3. **转动**：yaw / pitch 分开模拟。每轴为角加速度受限的速度控制器（目标角速度 ∝ 角差，裁剪到 `slew` 上限，变化率受 `accel` 限制），yaw 处理 ±π 回绕，越界就夹在 arc 边界。
4. **开火**：炮管实际指向与解算瞄准方向的夹角小于 `fireTol`（约 2× err），且目标在射界内、冷却完毕，就从炮口（`host.pos` + 机体坐标系 × `pos` + 炮管方向 × `barrel`）调用 `fireGunFrom`，带炮弹散布。转动途中照样可以开火。
5. 宿主在射程外 1.5 km 时整体休眠（不索敌），降低开销。

### A · 地表对地表攻击

### 4.1 目标选择
- `pickTargetFor` 拆成：
  - `pickAirTarget`：现有逻辑。
  - `pickSurfaceTarget`：扫 `world.targets`，要求 `hostile`、`ttype:'ground'`、存活、在武器射程内。
- 舰船的 kill 不归玩家，`killCredit` 识别 `source.kind === 'target'`。
- 舰船之间的战果在 radio 播报。

### 4.2 舰炮对地表（抛物线）
- 低伸弹道解：`tanθ = (v² − √(v⁴ − g(g·d² + 2h·v²))) / (g·d)`。无解（超射程）时不开火。
- 移动目标：用 `tof` 迭代求拦截点 2–3 次。
- 散布随距离增大：`spreadSurface ∝ d`，设置为 8 km 处 1σ ≈ 25 m。多发齐射才能命中，看起来像真的炮战。
- 炮弹沿用 `gravity` 子弹。命中或落水时调用 `Combat.blast`，落水有水柱特效。
- 为了让弧线好看又不飞太久，可以为舰炮弹单独设定 `gravity` 倍率（如 0.6），使 10 km 级射程的飞行时间在 10–15 s。

### 4.3 地对地导弹
- 发射器定义 `SHIPS[].launchers: [{ weapon, pos, mode:'vls' | {yaw, elev}, cells }]`。
- 起始姿态：
  - VLS：`fwd` = 世界上方，从甲板发射孔位置出生。
  - 斜发射架：按 yaw / elev 与舰体朝向计算。
- 飞行分三段：竖直或斜向助推约 1.2 s；以有限转率转平爬到 loft 高度（复用 `w.loft {alt, dive}`）；按 loft 规则俯冲制导。
- 新增 `launchT` 期间强制无制导，在 `stepMissile` 入口加一个分支。
- 现有 SAM（dl9 / ss6）也改为从 VLS 出生。现在是"朝目标 + 260 m 上方"直接射出，改完更好看。
- 新 NPC 武器 `ssm`：`target:'ship'`、loft、dmg 260、blast 20 / core 6、npcOnly。

> **已实施（v2.3 开发中）**：
> - 发射器写在 `SHIP_LAUNCHERS`（data.js），不并进 `SHIPS[].mounts`（mounts 的炮数要和 arms 文本对得上）。三种：`vls` 垂发、`{yaw, elev}` 斜置架、`turret` 旋转架（实体模型 `lnch` / `lnchr`）。全部跑在 Turret 运行时里，`SHIPS[].allMounts` 给预览用。
> - 舰空弹改成"受控"发射器（`cued`）：什么时候打、打谁仍由 `updateTargets` 按关卡的 weapon / fireCd 和发现规则决定，经 `Turret.cue` 交给垂发（当场出管）或旋转架（转到位再打）。没有发射器的船和地面阵地沿用旧路径。
> - `ssm` 定名 SPO-30 破浪；助推段 `launchT`（垂发至少 0.6 s），转平期间（`pitchOver`）不判丢失。
> - 舰载雷达：舰船发射的舰空弹射程 = min(锁定距离 × 1.5, 有效射程 × 0.9)。
> - 敌方舰炮对空要先有航迹：被对空雷达截获，或目标低空且在 5.2 km 内；近防炮不受限。中大口径炮对空射程（`airRange`）暂定 4 / 6 / 8 km，阶段 5 改成按射击包线。

### 4.4 两用炮决策（每个炮塔每 0.5 s 评分一次）
```
空中候选分 = 威胁度 × (1 / 转到所需时间)
   威胁度：6 km 内并且正在接近或已锁定本舰的飞机 = 1.0；其他飞机 = 0.4；来袭导弹在 CIWS 判定内处理
地表候选分 = 0.6 × (1 / 转到所需时间)，且只在 6 km 内没有威胁度 1.0 的飞机时参与
滞回：切换模式至少间隔 3 s；切换后要重新转动和解算，开火自然有延迟
```
- 同舰上有专职 `aa` 炮时，`dual` 主炮的地表权重 ×1.5，主炮更倾向打船。
- 舰船机动 v1 不改：仍按 route 航行，不做抢占射界的机动。

**关卡指定目标（命令）**

关卡可能要求 NPC 攻击指定单位，比如"敌舰炮击我方资产"、"我方舰队集火敌方旗舰"。指定目标是评分里的一个权重，不是覆盖规则，所以行为仍然自然：
- 数据：`t.orders = { target, mode:'prefer'|'only', weight, until }`，可以按炮塔 role 分开写，例如 `orders.surface`、`orders.air`。由 mission 的 `spawn` 或 `tick` 写入，`until` 写成到时或条件函数。
  - `prefer`：命令目标得分 × `weight`（默认 2.5）。威胁度 1.0 的飞机压近时，两用炮仍会转去自卫；近防炮对来袭导弹始终优先，不受命令影响。
  - `only`：该 role 的炮塔只打命令目标，射程或射界外就待机（转回零位或保持指向）。只给剧情需要的场合用，比如"不还手的炮击"。
- **自然表现**：
  - 命令目标在射程外时不乱射。有 route 的舰船按 route 接近；任务可以写一条朝目标的航路，或给 `orders.approach:true`，由舰船临时把下一个航点设成目标方向。
  - 命令下达或改变时加 0.5–1.5 s 的随机反应延迟，各炮塔错开，不会所有炮整齐地同一帧转向。
  - 首轮齐射散布 ×1.5，之后逐轮收敛到正常值，表现为"试射—修正"。
  - 命令目标被摧毁后，回到正常评分，不留空档。
  - 滞回照常生效：命令不会让炮塔在两个目标之间每帧来回切换。
- 同一套 `orders` 也给对空 SAM（`pickAirTarget`）使用，飞机 AI 已有的 `focus` 命令不动。
- 验证：
  - 探针一：敌舰带 `prefer` 命令炮击资产时，有飞机压近会分出火力对空，飞机离开后回到资产。
  - 探针二：`only` 命令下不会打其他目标。
  - 探针三：命令目标沉没后 2 s 内转打其他目标。

### B · 近防炮拦截导弹

### 4.7 混合方案
1. **交战判定**（`Turret.step` 中 role 为 `ciws`，并为来袭导弹优先）：
   - 导弹在 1800 m 内、处于射界内，且目标是本舰，或预计航迹在 300 m 内经过本舰，即进入候选。
   - 每门 CIWS 同时只交战 1 枚。导弹按"预计到达时间"排队，多门 CIWS 按最近者分配。
2. **概率：只在"已经对着导弹开火"时才掷骰**
   - 进入候选、分配到某门 CIWS，**不等于**开始判定。这门炮要先完成索敌反应（`react`），再按 3.3 节的转动模型把炮管转到解算方向。炮管夹角小于 `fireTol` 并且真的开始射击之后，才算"在打"。
   - 每门炮有一个"有效射击计时" `fireT`：只在本帧确实开火时（炮管对准、在射程和射界内、冷却完毕）才累加。每累加满 0.25 s 掷一次骰，然后从 `fireT` 里扣掉 0.25 s。
   - 导弹机动或横穿让炮管一时跟不上（夹角超过 `fireTol`），或短暂出了射界时，计时**暂停**、不清零。重新对准后接着累计。
   - 拦下一枚以后，转向下一枚还要重新转动和对准，这段时间不掷骰。所以多枚来袭时，后面的导弹天然地少挨几次判定，过载效应比原方案更强、也更真实。
   - 单次概率：
     ```
     p = P_BASE × speedK × aspectK
     P_BASE = 0.055                                   // 判定窗口被转动时间吃掉一截，基础值比原方案的 0.04 高
     speedK = clamp(600 / missile.speed, 0.5, 1.2)    // 越快越难打
     aspectK = 正对来袭 1.0，横穿 0.7
     ```
   - 估算：600 m/s 的导弹从 1800 m 打到 150 m，窗口约 2.75 s。扣掉反应和转动约 0.8 s，有效射击约 2.0 s，掷 8 次，单门拦截率约 36%。900 m/s 时窗口 1.83 s，扣掉 0.8 s 后掷 4 次，约 20%。从侧后方来、需要大角度转动的导弹会更低。这些数值以 probe-ciws 实测为准。
   - **过载**：门数少于来袭数时，多出来的导弹没有 CIWS 交战，直接突防。转火要花时间，进一步压低了齐射时的总拦截率。
3. **演出**：炮塔真实转向，对准后才开始持续发射 `fake:true` 曳光弹，和掷骰计时的起点一致，玩家看到开火就意味着已经在判定。曳光弹不参与 `scanShot`、不扣弹药或只扣象征性弹药，开销很低。判定成功后，导弹在 0.1–0.3 s 随机延迟后空爆（`Combat.blast`）。150 m 外空爆不会伤到本舰。
4. 拦截结果对玩家可见：自己的反舰弹被拦截时 HUD 提示 "INTERCEPTED"；我方舰队替玩家拦下导弹时 radio 播报。同时也做玩家其它的攻击反馈。玩家的导弹命中（不管是空中还是地表目标）时弹出HIT，击杀单位时显示KILL（KILL包含机炮击杀）。
5. 与 DEW 的关系：GUS-2 的逻辑不动，两者独立。
6. **与电子战压制的关系**：宿主舰被敌方干扰机压制时（`t.suppressed`，v1.13.x 起舰船也有这个值，已经按 `Ent.JAM_SURF_K = 0.5` 打过对折），近防也变差：
   - 单次概率再乘 `(1 − 0.6 × suppressed)`：火控雷达受扰，解算质量下降。
   - 索敌反应 `react` 乘 `(1 + suppressed)`：要更久才能确认目标。
   - 进入候选的距离不受影响。近防炮工作距离很近，基本都在舰船的烧穿距离（`Ent.JAM_BURN_SURF` 4500 m）以内，压不掉"看见"，只压"打准"。
   - 效果：干扰机伴随反舰攻击，能实打实地提高突防率。这是现实中反舰打击编组的标准做法。
   - probe-ciws 加一组：同样 2 枚来袭，`suppressed` 取 0 / 0.25 / 0.5，拦截率应单调下降。

> **已实施（v2.3 开发中）**：
> - 搜索雷达在 **3 km** 就把来袭弹交给近防（`CIWS_CUE`），提前转过去跟踪；开火和掷骰仍在 1800 m 内。只在 1800 m 才开始索敌时，反应加转动要吃掉 0.8–1.6 s，有效射击只剩 0–5 次骰，侧面来袭几乎拦不下。
> - `P_BASE` 实测定为 **0.08**（计划起步值 0.055）：ssm 在低空约 744 m/s，`speedK` 只有 0.81。
> - 拦截成功的弹在 0.1–0.3 s 后空爆（`stepMissile` 的 `ciwsKill`），报 `intercept` 事件。
> - 反馈走 `world.events`，由 `combatEvents` 消化：自己的弹被拦 → INTERCEPTED；玩家的弹（导弹 / 炸弹）打中东西 → HIT（同帧有 KILL 时不报）；KILL 加上了地面 / 海面目标；我方舰船拦下敌弹 → radio（8 s 内只报一次）。
> - `tools/probe-ciws.js` 实测（Orca 两门，每组 40 次）：ssm 单枚 30–38%，900 m/s 约 20%，4 枚齐射约 19%；压制 0 / 0.25 / 0.5 → 35% / 30% / 22%。
> - 演出没有用 `fake:true` 曳光：近防打的是真子弹，流弹照样能打到飞机。

### C · 舰船尾部螺旋桨水花

### 4.8 尾流水花特效
- 目标：舰船航行时，在 3D 模型尾部（螺旋桨位置）持续冒出白色翻滚水花，速度越快越明显，停船时消失。纯演出，不参与碰撞和伤害。
- 数据：`SHIPS[].props: [{ x, z }]`，螺旋桨在模型局部坐标的位置（通常在舰尾水线下方，单轴或双轴）。没写时按 `dim` 推导：舰尾 `-len/2 × 0.92`，双轴左右各 `beam × 0.18`。
- 生成：
  - 每艘舰每帧按 `rate = RATE_MAX × clamp(speed / maxSpeed, 0, 1)` 发射粒子，`RATE_MAX` 起步 30 个/秒/轴。航速低于 2 m/s 不发射。
  - 粒子出生在螺旋桨位置后方 2–4 m 的水面（y = 海面 + 0.3），带少量随机横向速度和向上初速（1–3 m/s），受重力落回水面。
  - 外观：白色 / 浅青色半透明圆片，出生时小、0.6–1.2 s 内放大 2–3 倍并淡出，形成从舰尾往后拖开的一道翻腾白带。
  - 远处降级：玩家距离 3 km 以外减半，6 km 以外只画一条简化的平面尾迹带或不画。粒子总数设上限（如全场 600），超出时丢最老的。
- 复用现有粒子 / 烟雾系统的池子，不新开渲染路径；如果现有系统只有烟雾，新增一个 `kind:'spray'` 分支，颜色和重力不同。
- 舰船受损沉没时停止发射；高速转向时外侧一轴的发射率 ×1.3，让转弯尾迹略不对称。
- 验证：smoke 跑一艘 Orca 全速航行 10 s，断言粒子数稳定在上限以下；截图检查舰尾有连续水花、停船后 2 s 内消失；帧时间与关闭特效时相比增加不超过 5%。

> **已实施（v2.3 开发中）**：`Ent.wakeSpray`（entities.js），由 `updateTargets` 对 `t.ship` 调用。螺旋桨位置按 `dim` 推导（60 m 以上双轴），没有单独写 `props` 的船。全场粒子超过 500 时停发（爆炸特效 650 起降级，给它留余量），没有另设 600 的水花上限。smoke：Orca 全速 10 s，峰值约 60 个粒子，停船 2 s 内消失。

3. **压制降低近防拦截率**：见 4.7 第 6 条。
4. **数据链降级**：舰队里一艘被压制，它给编队共享的目标信息延迟或丢失。这块要等舰队协同（4.1 的目标选择）做完再说。

## 阶段 5 · v2.4 炮弹与导弹的高度物理

起因（2026-10-19 讨论）：现在的物理只做了"高空转不动"这一半。导弹滑翔段掉速和高度无关，低空反而速度上限更高；炮弹没有阻力，对空射程是一个和仰角无关的直线距离。

**现状与目标对照**

| 方面 | 现实 | 现状 | 目标 |
|---|---|---|---|
| 导弹转弯能力 | 随动压下降，高空难转 | `turnFactor` = √(ρ/ρ0)，保底 0.34 | 保持 |
| 导弹滑翔段掉速 | 随动压，低空快、高空慢 | 固定 140 m/s²，与高度无关 | 按空气密度缩放 |
| 导弹转弯的速度代价 | 诱导阻力随动压 | 最多 62 m/s²，与高度无关 | 按空气密度缩放 |
| 导弹动力段速度上限 | 低空阻力大，极速更低 | 海平面比 12 km 以上高 20% | 去掉低空加成或反向 |
| 冲压弹（CLA-17） | 推力随空气密度连续变化，中高空效率最好 | 18 km 以上动力段从 10 s 硬切到 2.4 s | 连续过渡 |
| 舰炮对空射程 | 随仰角变化：平射远、仰射近，有射高上限 | 只比直线距离（`airRange`） | 按射击包线 |
| 炮弹弹道 | 有空气阻力 | 只有重力 | 加阻力 |
| 对地导弹 / 滑翔炸弹弹道 | 投放高度和速度决定能滑多远，阻力随高度变 | 有动力的对地弹同空空弹（滑翔段固定掉速）；无动力弹只在阻力里乘了空气密度，升力没有建模 | 和 5.1 同一套阻力，滑翔弹加升阻比 |
| 自由落体制导炸弹（PEJ-30） | 基本是抛物线，尾翼只能在落点附近修正一圈 | 制导时直接转速度矢量，修正能力和弹翼无关 | 尾翼修正量受动压限制，不能把抛物线掰成滑翔 |
| 无制导炸弹 / 火箭的瞄准 | 有连续计算的落点（CCIP） | HUD 没有落点，全凭感觉 | 动态预计落点 |
| HUD 发射包线（IN RNG / NEZ） | 由载机高度、速度、目标高度和距离共同决定 | 空空弹按一套经验公式；对地弹按"当前高度平飞发射"的有效射程 × 0.7，不看目标高度 | 用新物理动态计算 |

### 5.1 导弹
1. 滑翔段掉速（现为 140 m/s²）和转弯掉速（现为最多 62 m/s²）乘一个空气密度系数。以现有数值对应中空（约 6–8 km）为基准：低空放大、高空缩小，并设上下限。`highAltImmune` 的低空惩罚并入这条，不再单列。
2. 动力段速度上限的低空加成（`1 + (12000 − y)/60000`）去掉，或改成高空略高。
3. **冲压弹连续过渡**：`effectiveLife` 的 18 km 硬门槛改成按空气密度连续变化的推力 / 燃烧时间曲线。中高空（约 10–20 km）最好；更高处推力逐渐不足；低空推力足，但阻力大，相对更费燃料。CLA-17 的文案（"18 公里以上降级为火箭模式"）同步改写。
4. `effRange`（AI 射程）、HUD 包线（`computeEnvelope`）、机库射程（`missileRange`）都读同一套弹道，会跟着自动变化。改完重新核对各弹的射程定位。

### 5.2 炮弹
1. 炮弹加空气阻力（按空气密度和速度），舰炮 `gravity` 倍率按需要重调。
2. **射击包线**：每门炮用真实弹道代码，在一组仰角上模拟，记下引信时间内仍有可用速度的最远斜距，按炮缓存（做法同导弹的 `effRange`）。
3. 火控按目标的仰角和距离查包线，代替单一的 `airRange`。拦截解算的 `tof` 也改用模拟值。
4. 结果：平射远、仰射近，自然出现射高上限，爬高成为躲炮的手段。

### 5.3 对地导弹与滑翔炸弹
1. 有动力的对地 / 反舰弹（agm、asm）沿用 5.1 的阻力和掉速，高抛（`loft`）弹道在高空滑行段的收益自然出现。
2. 无动力制导弹（滑翔炸弹，`ballistic` 且有导引头，如 GUT-9、PEJ-30）加一个**升阻比**：
   - 现在只有重力和阻力，滑翔距离全靠投放初速，几乎是抛物线。
   - 改成按升阻比把下沉转成前进：高空投放、速度越快滑得越远，低空投放只剩一小段。
   - 制导时的转弯同样消耗速度（与导弹同一条），所以末段大角度修正会缩短射程。
3. **自由落体制导炸弹**（PEJ-30 铁蒺藜，光电制导、无弹翼）：
   - 不加升力，弹道基本是投放速度决定的抛物线。
   - 现在的制导是直接把速度矢量转向目标、只限转弯率，这让它实际上能"掰弯"抛物线、近似滑翔。改成尾翼只产生一个受动压限制的侧向加速度：能修正落点附近一圈的误差（几十到一两百米，按投放高度和速度），但修不回投放时就偏离很多的瞄准。
   - 结果：它的有效射程主要取决于投放高度和速度，"在目标上空附近投放"成为必须，和滑翔弹的定位区分开。
4. 无制导炸弹（PEJ-9 碎玉）不加升力，只换成 5.1 的阻力模型。无制导火箭（PEJ-6 撒星）动力段按推力 − 阻力积分，熄火后走同一套阻力。
5. `effRange` 对这些弹照样用真实弹道代码模拟，AI 的投放距离跟着变。

### 5.4 HUD 发射包线动态计算
现在的包线（`hud.js` 的 `computeEnvelope`）：空空弹按动力段距离和目标背离速度的经验公式；对地弹只用"本机当前高度平飞发射"的有效射程，NEZ 取其 70%。

改成基于 5.1–5.3 的物理动态算：
1. **输入**：本机高度、速度、俯仰（投放 / 发射姿态），目标高度、水平距离、相对速度和航向。
2. **方法**：用真实弹道代码，从本机当前状态对目标当前位置做一次快速模拟（或者查按高度 / 速度 / 高度差分档缓存的包线表，避免每帧全量模拟）：
   - rmax：弹飞到目标时仍有可用速度（导弹）或还够得着（炸弹）的最远距离。
   - NEZ：空空弹假设目标立刻掉头逃逸仍能追上的距离；对地 / 对海目标用目标最大航速代替逃逸。
3. **效果**：高处俯冲投放的射程显著大于低空平飞；目标比本机高时射程缩短；从下往上打高空目标的 NEZ 明显变小。
4. 机库的射程显示（`missileRange`）和 AI 的开火距离（`aiReach`）尽量读同一套结果，三处不再各算各的。

### 5.5 无制导武器的预计落点（CCIP）
适用：无制导炸弹（PEJ-9）和无制导火箭（PEJ-6）。依赖 5.3 的弹道：落点必须和真实弹道是同一套计算，否则标记会骗人。
1. **计算**：每帧从本机当前的位置、速度、姿态出发，用与 `stepMissile` 相同的积分（重力、阻力，火箭加推力）前推，直到弹道穿过海面（y = 0）或目标高度，得到预计落点。步长放大（例如 0.05 s）并设步数上限，保证每帧开销可控；超出寿命仍未落地就不显示。
2. **显示**：
   - 落点投影到屏幕上，画一个小圆（pipper），和机头之间连一根落点线。
   - 子母弹再画出抛撒覆盖半径（`cluster`），投影成地面上的椭圆，直接看出能盖住哪些目标。
   - 落点在屏幕外时，在屏幕边缘给方向提示。
   - 有锁定 / 选中目标时，落点圈与目标重合（或目标落进覆盖圈）就变色，表示"现在投 / 现在打能中"。
3. 只在当前武器是无制导炸弹 / 火箭时显示，不和制导弹的视场圈同时出现。
4. 火箭的落点用来瞄准海面目标；空中目标不在这条线的考虑里。

### 5.6 新增两种高爆无制导自由落体炸弹
现在唯一的无制导炸弹是子母弹（PEJ-9），它是"覆盖面、每个目标吃满额"的特殊打法。补两种普通高爆炸弹，让 5.5 的落点标记有常规的用武之地：

| | 定位 | 威力 / 范围 | 携带量 |
|---|---|---|---|
| 轻型高爆炸弹 | 多带、多投，打小目标和分散目标 | 小当量，`blast` 小 | 总携带量多（`ammo` / `perPoint` 大），冷却快（`STORE_COOLDOWN` 短） |
| 重型高爆炸弹 | 一次投放打大目标或密集目标 | 大当量，`blast` 大、`blastCore` 大 | 总携带量少，冷却慢，只能挂重挂点 |

- 都是 `ballistic`、`unguided`、无导引头，走 5.3 的弹道和 5.5 的落点标记。没有子母弹的抛撒：落点中心起爆，按 `Combat.blast` 的距离衰减结算。
- 编号、名字、挂点适配（`STORE_ATTR`）、外观（`look`）、冷却（`STORE_COOLDOWN`）、图鉴文案按现有武器的规矩补齐。命名用对地弹的 PEJ- 词根，序号和现有的 PEJ-6 / 9 / 30 错开。
- 数值以重型弹能单枚重创一艘护卫舰级、轻型弹需要多枚才能击沉小艇为起点，跑 probe-blast 和 probe-balance 校。
- AI 不选无制导弹（`chooseWeapon` 的设计约束），这两种只给玩家用；NPC 不挂。

### 5.7 验证
- probe-balance：各导弹在 0 / 6 / 12 / 18 / 24 km 的有效射程表，改前改后对比；高空射程应明显大于低空。
- 冲压弹射程随高度连续变化，没有台阶。
- 滑翔炸弹：同一速度下 3 / 8 / 12 km 投放的滑翔距离递增；低空投放射程明显变短。
- 铁蒺藜：同一高度和速度投放，偏离目标越远命中率越低；修正半径随投放高度增大。
- 落点标记：对静止的海面目标，在标记套住目标的那一刻投放 / 发射，实际落点与标记的偏差在弹体散布以内（探针在多种高度、速度、俯冲角下抽样）。
- HUD 包线：同一目标、本机高度 / 速度 / 目标高度各变一项，rmax / NEZ 变化方向正确；在 HUD 显示 IN RNG / NEZ 的距离上实际发射，命中率与显示一致（探针抽样）。
- probe-turret：各炮在不同仰角的射击包线；对飞机命中率重新落进 3.8 节的区间。
- smoke 全绿；probe-missions 难度回归，重点看有舰船的关卡和高空截击关。
