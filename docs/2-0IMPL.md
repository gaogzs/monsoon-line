# 2.0 实施计划

对应 [2-0PLAN.md](2-0PLAN.md)。本文是落地方案：分阶段、每阶段独立发布、每步都能玩能验。数值都是**起步值**，以各阶段的探针脚本实测为准再调。

已定的决策：
- 分阶段小版本：1.12 抗性 → 1.13 爆炸/近炸 → 1.14 炮塔 → 2.0 舰对舰 + 近防拦截 + 舰船尾部水花 + 海上平台 + 新关卡。
- 近防炮拦截用**混合方案**：按概率判定，炮塔真实转向并打出曳光"配合演出"。只有炮管已经对准导弹、真正开火之后才开始定时掷骰。
- 动能杀伤弹**只在设定上是动能**。伤害固定，不按相对速度计算。

## 阶段 1 · v1.12 机炮抗性

### 1.1 基础设施
> **已实施（v1.12）**：机炮抗性只在 `scanShot` 一处结算，落成 `Ent.gunResistK`（entities.js），没有提前建 `combat.js`。伤害收口和 `js/combat.js` 挪到阶段 2，和 blast 一起做。

1. 新建 **`js/combat.js`**（在 entities 之后、game 之前加载），收口伤害：
   ```js
   // info: { kind:'gun'|'blast'|'direct', w: weaponDef|null }
   Combat.apply(ent, amt, world, source, info)
     → amt *= Combat.resistK(ent, info)   // 机炮抗性
     → ent.kind==='target' ? hitTarget路径 : Ent.damage路径（JDA-3 armor 仍在 Ent.damage 内另乘）
   Combat.resistK(ent, info) = (info.kind==='gun' && info.w && info.w.cal <= SMALL_CAL) ? 1 - ent.gunResist : 1
   ```
   常量 `SMALL_CAL = 40`（mm）。75mm 以上舰炮不吃机炮抗性。
2. 所有机炮武器加 `cal` 字段：k3/k1/k2 = 20，k7/k11 = 30。
3. `fireGun` 生成子弹时带上 `w` 和 `cal`（`entities.js:1683`）。
4. `scanShot`（`game.js:2387/2418`）、`hitAny`、`detonate`、`clusterBurst` 都改为调用 `Combat.apply`。`bombTheBase`（`missions.js:179`）用 `kind:'direct'`。
5. 字段 `gunResist ∈ [0, 0.999]`：
   - 飞机写在 `AIRCRAFT[].phys.gunResist`，由 `makeAircraft` / `spawnEnemy` 复制。
   - 舰船写在 `SHIPS[].gunResist`，由 `spawnShip` 复制。
   - 地面设施在 `spawnTarget` 调用处传入。
   - 调节单元在 `spawnCellField` 里设置。
   - 缺省为 0。

## 阶段 2 · v1.13 范围伤害与近炸引信

### 2.1 新字段（替代旧 `prox`）
| 字段 | 含义 |
|---|---|
| `fuze` | 近炸触发半径（m，测到目标表面）。0 / 缺省 = 只有直接碰撞才起爆 |
| `blast` | 爆炸半径（m，测到受害者表面）。0 = 无溅射，只伤害直接命中的目标 |
| `blastCore` | 满伤半径（m） |
| `blastAir` | 默认 true。false = 只伤地表（子母弹） |

衰减：令 `d = max(0, 距离 − 受害者半径)`。
```
d <= core       → k = 1
core < d < R    → x = (d−core)/(R−core);  k = (1−x)²      // 二次衰减：破片密度和能量同时下降
d >= R          → k = 0
```
受害者半径：飞机统一用 `HIT_R_AIR = 7.5`（与 scanShot 一致，做成常量），地表目标用 `tg.radius`。

### 2.2 机制
1. **`Combat.blast(world, pos, w, source)`**：遍历 `actors` 和 `targets`，跳过 `team === source.team`（与子弹的 `team !==` 规则一致，中立单位照样会被炸到）和发射者本人。每个受害者的伤害为 `dmg × k × warheadK × antiRadar`，类型 `kind:'blast'`，不吃机炮抗性。直接命中的目标 `k` 取 1。
2. **近炸：在最近的那一刻起爆**
   - 每帧对导弹和目标的相对运动做线段最近点计算，避免 700 m/s 时每帧 12 m 的穿越漏判。本帧最近距离 < `fuze`，并且最近点落在本帧内（相对距离由减转增），就在最近点起爆。
   - 直接撞上（与目标表面的距离 < 1.5 m）当帧起爆，按满伤处理。
   - 只检测导弹自己的目标（或下面第 3 条的诱饵），沿用现状，不对路过的其他飞机触发。爆炸伤害本身会波及附近所有人。
   - **不做任何人为偏移**：制导照常瞄准目标，该正中就正中，打不机动的目标时直接命中满伤是对的。伤害的分布来自真实的脱靶因素：
     - 目标机动，导弹转向率和速度跟不上（现有的 `turnFactor`、转弯掉速）；
     - 一阶提前量（`w.lead`）对加速或转弯中的目标有误差；
     - 导引头视场丢失、诱饵、重捕获造成的末段扰动。
     机动越狠，脱靶越远，伤害越低。这正是"擦肩而过不够、要真正甩开"的体验来源。
   - 验收：probe-blast 按目标机动档统计"起爆距离 / 爆炸半径"的直方图。
     - 不机动：以直接命中为主。
     - 一般机动和急转：比值要有明显分布，标准差 ≥ 0.15 × blast，并且随机动强度变大，平均伤害单调下降。
     - 如果急转档的分布仍然太集中，说明近炸半径相对导弹的跟踪误差太大，调 `fuze` / `blast` 的比例，不加偏移。
3. **打上干扰弹也会正常爆炸**：现在被热焰弹或箔条骗走的导弹只是 `target = null` 盲飞，到寿命结束都不会炸（`entities.md:377`），干扰弹云只用于后面的重捕获判定（`decoyRecheck`）。改成：
   - 被骗时 `breakLock` 已经记下了 `m.decoy`（位置 `p`、速度 `v`、起始时刻 `t0`）。在盲飞期（`reLockT > 0`）内，导弹把 `decoy` 当前的外推位置 `p + v × (age − t0)` 当作虚拟目标继续制导，转向和速度损失照常计算，而不是直飞。
   - 对虚拟目标也做第 2 条的最近点近炸。诱饵视为半径 4 m 的球，触发半径同样是 `fuze`，在离诱饵最近的那一刻起爆，然后调用 `Combat.blast`。
   - 后果是爆炸会波及附近的人。干扰弹投得太晚，诱饵还在机身旁边，导弹在诱饵上炸开照样会溅到自己。这让"什么时候投弹"有了分量：提前投可以完全躲开，贴脸才投就是赌。
   - 诱饵熄灭（超过 `DECOY_LIFE`），或者盲飞期内重新咬住真目标（`decoyRecheck` / 重捕获），就切回真目标或恢复搜索，不再追诱饵。
   - 电子干扰（`openEcm`）这类没有实体诱饵的欺骗不变：导弹盲飞，寿命结束时在空中自爆（第 4 条）。
   - 验收：probe-blast 增加一组"投弹时机"实验，热焰弹分别在距离 3 km、1 km、300 m、100 m 时投放，统计投弹机受到的平均伤害。期望早投接近 0、贴脸投明显大于 0，并且曲线单调。
4. 撞地 / 撞海、寿命结束（包括电子干扰后盲飞到期），都调用 `Combat.blast`。现在这些情况是哑弹（`entities.md:377`）。
5. `clusterBurst` 删掉，改为 `blast = cluster`、`blastCore = cluster`（平伤）、`blastAir = false`。
6. 非制导火箭和炸弹走 `scanShot` 命中或撞地，再调用 `Combat.blast`，没有 `fuze`。
7. 玩家处于爆炸半径内受伤时：屏幕抖动 + 受伤闪烁（已有受伤反馈的话复用）。

### 2.3 数值迁移（空空弹）
目标："擦肩而过不够"，同时**平均交付伤害与现在持平（±10%）**，不整体加强或削弱导弹。

| 档 | 武器 | fuze | blast | core | dmg |
|---|---|---|---|---|---|
| 格斗弹 | srm trm hos qsr swm wasp v11 v9 otr dl6 vbn | 旧 prox×0.6 | fuze + 6 | 2 | 实测补偿，约 +10% |
| 中距 | mrm dl4 v17 dl9 ss6 | 旧 prox×0.7 | fuze + 12 | 4 | 实测补偿 |
| 重型拦截 | arm vlar hva | 旧 prox×0.8 | fuze + 22 | 7 | 实测补偿 |

旧 prox 的实际含义是"进入 prox+6 就打满伤害"。新方案缩小了触发半径，但伤害能伸到更远、而且越远越轻。所以 dmg 要靠探针校准，不能拍脑袋定。

### 2.6 爆炸特效与伤害范围同步
现在所有弹头起爆都调用同一个 `explode(list, pos, scale, count)`（`entities.js:1805`），scale 基本写死为 1.0 到 1.4。画面上爆炸多大，和伤害打多远没有关系。改完以后，玩家应该能从画面上读出"这一发炸多大"。画面不必和数值完全一致，但要成比例。

1. **新函数 `Ent.blastFx(world, pos, w, opts)`**，放在 `combat.js`。`Combat.blast` 起爆时调用它，原来直接调 `explode` 的起爆点（`detonate`、撞地、`clusterBurst` 的替代）也统一改调它。尺寸全部从武器的 `blast` / `blastCore` 推出来，不需要逐个武器配置特效。
2. **火球（偏小）**：目视半径 `ballR = clamp(0.35 × blast, blastCore, 0.5 × blast)`，并且不小于 4 m。
   - 现在 scale 1 的火球大约扩散 26 m（粒子初速最高 58 m/s，按 `stepParticles` 的阻力 2.2 反算），所以换算成 `scale = ballR / 26`。
   - 粒子数 `count ∝ √scale`，在 10 到 28 之间夹紧。
   - 火球故意比伤害范围小：中心那团火是"满伤区"的提示，外围靠破片表现。
3. **破片壳（球形扩散）**：一圈小而亮的粒子从爆心均匀地向外飞，飞到 `blast` 附近消失。
   - 方向用 Fibonacci 球面分布加小抖动，比纯随机更像一个均匀膨胀的球壳，也不会出现明显空洞。
   - 初速和寿命按阻力模型反算，让最远飞行距离约等于 `blast`：线性阻力下最远距离 = `v0 / drag`，所以取 `v0 = blast × dragFrag`。`dragFrag` 取 3–4，破片会先快后慢，最后停在半径附近。寿命取到速度衰减到约 10% 为止。
   - 外观：0.5–1.2 m 的亮点，颜色从 `#fff2c0` 渐变到灰色，不膨胀（`grow:false`），不受重力，或只受很小的重力。如果渲染器支持按速度拉长成短线，就画成短线，看起来更像破片。
   - 数量按 blast 档位：格斗弹 24，中距弹 36，重型弹和中距重战斗部弹 56，对地重弹 40。
   - 破片壳叠加 30% 的弹体速度，这样高速掠过时的爆炸是一个被拖长的椭球，比原地停住的球自然。
4. **按弹种区分**：
   - 空空弹：完整球壳。
   - 对地 / 反舰弹撞地或落水：只取上半球的方向（半球壳），再加一点尘土或水花粒子。落水时加一根竖直水柱，高度约 0.6 × blast。
   - 子母弹（`blastAir:false`、平伤）：不画一个大球。在 cluster 半径内随机撒 6–10 个小爆点，每个用小火球加少量破片，起爆时间在 0–0.3 s 内错开，看起来像一片子弹药依次炸开。
   - 动能杀伤弹（`blast 0`）：没有火球和破片壳。命中时画一个短促的白闪加少量碎屑火花；没命中就什么都没有。
   - 大口径炮弹空爆（阶段 3）：沿用同一个函数，按 n50 / n75 / n120 的 blast 自动缩放，对空射击时天上出现一团团大小不一的烟团。
5. **烟团**：保留现在的深灰烟团，大小跟着 `ballR` 走，停留时间稍长，用来事后标记"刚才在这里炸过"。
6. **预算和细节等级（LOD）**：
   - 粒子总上限仍是 900（`compact`）。
   - `blastFx` 先看当前粒子数：超过 650 时破片数减半，超过 800 时只画火球。
   - 距相机超过 6 km 时破片数减半，超过 12 km 时不画破片。
   - 齐射（比如 8 枚同时起爆）不能挤掉玩家身边正在发生的爆炸。
7. **玩家视角**：玩家在 blast 范围内时，破片会从机身旁飞过，配合 2.2 节第 7 条的屏幕抖动，玩家能感觉到"这一下擦到了"。
8. **可调参数**：`BLAST_FX = { ballK:0.35, ballMaxK:0.5, fragDrag:3.5, fragN:{…}, lod:{…} }` 集中放在 `combat.js` 顶部。个别武器需要特殊外观时，可以在武器数据里写 `fx:{ ballK, fragN }` 覆盖，但默认不写。
9. **验证**：
   - smoke：用 `stepParticles` 把一次 `blastFx` 推进到结束，统计破片最远飞行距离，应在 [0.8, 1.15] × blast 之间；火球粒子最远距离应 ≤ 0.55 × blast。8 发齐射时粒子总数不超过上限，并且 LOD 生效。
   - 手动：格斗弹、中距弹、重型弹、子母弹、落水各截一张图，对比三档空空弹的球壳大小，确认能一眼区分。

## 阶段 3 · v1.14 旋转炮塔与多炮塔

### 3.1 前置重构
- `Ent.fireGunFrom(shooter, w, muzzlePos, dir, world)` 作为生成子弹的核心。`fireGun(a, world)` 改为用机头位置和 `a.fwd` 调用它，行为不变。
- 子弹支持 `gravity`（倍率）、`fuze`、`blast`、`cal`、`w`，供大口径炮弹使用。
- 只有带 `fuze` 的炮弹才对 actors 做近炸检测，开销可控。

### 3.2 数据结构（新文件 `js/turret.js`，数据放 `data.js` 的 `TURRET_GUNS`）
挂在单位定义上：`SHIPS[].mounts` / `AIRCRAFT[].mounts`。
```js
mounts: [{
  id: 'ciwsF', gun: 'ciws20',
  pos: [0, 9.2, 52],            // 模型空间：船头 +z，右舷 +x，上 +y，单位 m
  yaw0: 0,                      // 零位朝向（弧度，相对船头）
  arc: { yawMin:-2.6, yawMax:2.6, pitchMin:-0.1, pitchMax:1.45 },
  slew: { yaw:1.6, pitch:1.2, accel:3.0 },    // 最大角速度 rad/s、角加速度 rad/s²
  model: null | 'tur75',  barrel: 4.2,         // 有实体时炮弹从炮口射出
  role: 'aa' | 'surface' | 'dual' | 'ciws',
  aim: { err: 0.004, lag: 0.5, react: 0.6 }   // 瞄准噪声σ、速度滤波时间常数、索敌反应时间
}]
```
运行时状态 `{ yaw, pitch, wYaw, wPitch, target, scanT, cd, ammo, vEst, noise }`，在 `makeTarget` / `makeAircraft` 里由 `Turret.make` 生成，挂到 `ent.turrets`。

### 3.3 每帧逻辑 `Turret.step(tu, host, world, dt)`
1. **索敌**：每 `react` 秒一次，带抖动错开。在射程 + 余量内、射界内、按 role 过滤的敌对单位中，按"转到目标所需时间 + 距离权重"打分，选最低者。当前目标仍有效时保留（滞回）。
2. **提前量**：
   - 不读目标真实速度，而用滤波速度 `vEst += (t.vel − vEst) × dt/lag`。这一项天然产生迟钝：匀速平飞时 `vEst` 收敛，必中；缓慢转弯或加速时滤波滞后加上纯直线外推，有小偏差；乱机动时 `vEst` 总是落后，基本打不中。
   - 拦截点用 2 次迭代：`tof = dist/v_shell`，`aim = t.pos + vEst×tof`，再加炮弹下坠补偿 `+½ g·gravity·tof²`。
   - 瞄准噪声：OU 过程（均值回归的平滑随机游走）叠加在瞄准方向上，σ = `aim.err`，让误差是缓慢漂移而不是逐发跳动。
3. **转动**：yaw / pitch 分开模拟。每轴为角加速度受限的速度控制器（目标角速度 ∝ 角差，裁剪到 `slew` 上限，变化率受 `accel` 限制），yaw 处理 ±π 回绕，越界就夹在 arc 边界。
4. **开火**：炮管实际指向与解算瞄准方向的夹角小于 `fireTol`（约 2× err），且目标在射界内、冷却完毕，就从炮口（`host.pos` + 机体坐标系 × `pos` + 炮管方向 × `barrel`）调用 `fireGunFrom`，带炮弹散布。转动途中照样可以开火。
5. 宿主在射程外 1.5 km 时整体休眠（不索敌），降低开销。

2. 近防炮拦截导弹（4.7）
3. 舰船尾部螺旋桨水花特效（4.8）
4. 各势力固定式海上平台（4.9）
5. 平衡回归与新关卡（4.10–4.12）

### A · 地表对地表攻击

### 4.1 目标选择
- `pickTargetFor` 拆成：
  - `pickAirTarget`：现有逻辑。
  - `pickSurfaceTarget`：扫 `world.targets`，要求 `hostile`、`ttype:'ground'`、存活、在武器射程内。
- 舰船的 kill 不归玩家，`killCredit` 识别 `source.kind === 'target'`。
- 舰船之间的战果在 radio 播报。

### 4.2 舰炮对地表（抛物线）
- 低伸弹道解：`tanθ = (v² − √(v⁴ − g(g·d² + 2h·v²))) / (g·d)`。无解（超射程）时不开火。
- 移动目标：用 `tof` 迭代求拦截点 2–3 次。
- 散布随距离增大：`spreadSurface ∝ d`，设置为 8 km 处 1σ ≈ 25 m。多发齐射才能命中，看起来像真的炮战。
- 炮弹沿用 `gravity` 子弹。命中或落水时调用 `Combat.blast`，落水有水柱特效。
- 为了让弧线好看又不飞太久，可以为舰炮弹单独设定 `gravity` 倍率（如 0.6），使 10 km 级射程的飞行时间在 10–15 s。

### 4.3 地对地导弹
- 发射器定义 `SHIPS[].launchers: [{ weapon, pos, mode:'vls' | {yaw, elev}, cells }]`。
- 起始姿态：
  - VLS：`fwd` = 世界上方，从甲板发射孔位置出生。
  - 斜发射架：按 yaw / elev 与舰体朝向计算。
- 飞行分三段：竖直或斜向助推约 1.2 s；以有限转率转平爬到 loft 高度（复用 `w.loft {alt, dive}`）；按 loft 规则俯冲制导。
- 新增 `launchT` 期间强制无制导，在 `stepMissile` 入口加一个分支。
- 现有 SAM（dl9 / ss6）也改为从 VLS 出生。现在是"朝目标 + 260 m 上方"直接射出，改完更好看。
- 新 NPC 武器 `ssm`：`target:'ship'`、loft、dmg 260、blast 20 / core 6、npcOnly。

### 4.4 两用炮决策（每个炮塔每 0.5 s 评分一次）
```
空中候选分 = 威胁度 × (1 / 转到所需时间)
   威胁度：6 km 内并且正在接近或已锁定本舰的飞机 = 1.0；其他飞机 = 0.4；来袭导弹在 CIWS 判定内处理
地表候选分 = 0.6 × (1 / 转到所需时间)，且只在 6 km 内没有威胁度 1.0 的飞机时参与
滞回：切换模式至少间隔 3 s；切换后要重新转动和解算，开火自然有延迟
```
- 同舰上有专职 `aa` 炮时，`dual` 主炮的地表权重 ×1.5，主炮更倾向打船。
- 舰船机动 v1 不改：仍按 route 航行，不做抢占射界的机动。

**关卡指定目标（命令）**

关卡可能要求 NPC 攻击指定单位，比如"敌舰炮击我方资产"、"我方舰队集火敌方旗舰"。指定目标是评分里的一个权重，不是覆盖规则，所以行为仍然自然：
- 数据：`t.orders = { target, mode:'prefer'|'only', weight, until }`，可以按炮塔 role 分开写，例如 `orders.surface`、`orders.air`。由 mission 的 `spawn` 或 `tick` 写入，`until` 写成到时或条件函数。
  - `prefer`：命令目标得分 × `weight`（默认 2.5）。威胁度 1.0 的飞机压近时，两用炮仍会转去自卫；近防炮对来袭导弹始终优先，不受命令影响。
  - `only`：该 role 的炮塔只打命令目标，射程或射界外就待机（转回零位或保持指向）。只给剧情需要的场合用，比如"不还手的炮击"。
- **自然表现**：
  - 命令目标在射程外时不乱射。有 route 的舰船按 route 接近；任务可以写一条朝目标的航路，或给 `orders.approach:true`，由舰船临时把下一个航点设成目标方向。
  - 命令下达或改变时加 0.5–1.5 s 的随机反应延迟，各炮塔错开，不会所有炮整齐地同一帧转向。
  - 首轮齐射散布 ×1.5，之后逐轮收敛到正常值，表现为"试射—修正"。
  - 命令目标被摧毁后，回到正常评分，不留空档。
  - 滞回照常生效：命令不会让炮塔在两个目标之间每帧来回切换。
- 同一套 `orders` 也给对空 SAM（`pickAirTarget`）使用，飞机 AI 已有的 `focus` 命令不动。
- 验证：
  - 探针一：敌舰带 `prefer` 命令炮击资产时，有飞机压近会分出火力对空，飞机离开后回到资产。
  - 探针二：`only` 命令下不会打其他目标。
  - 探针三：命令目标沉没后 2 s 内转打其他目标。

### 4.5 关卡与图鉴
- 新增 NPC 武器（ssm、n50、n75、n120 等）不进挂载图鉴：inv2 的 NPC 表过滤 `npcOnly`。

- 关卡钩子：`mission.tick` 里可以读 `t.engaged`，用于"敌舰正在炮击资产"的 radio 提示。

### 4.6 验证
- 探针：两艘相距 8 km、对向航行的驱逐舰，60 s 内双方都有命中且都不会秒沉；炮弹弧线峰值高度合理（截图检查）。
- SSM：发射姿态正确（VLS 竖直出管）、弧线合理、能命中移动舰船。
- 两用炮：有飞机压近时转去对空，飞机离开后 3 s 以上再回到打船。
- probe-missions 全绿，旧关卡里我方 / 敌方舰船互相开火不会改变胜负条件。必要时在旧关卡把双方舰船拉到射程外，或给 `mission` 加 `surfaceFire:false` 开关。

### B · 近防炮拦截导弹

### 4.7 混合方案
1. **交战判定**（`Turret.step` 中 role 为 `ciws`，并为来袭导弹优先）：
   - 导弹在 1800 m 内、处于射界内，且目标是本舰，或预计航迹在 300 m 内经过本舰，即进入候选。
   - 每门 CIWS 同时只交战 1 枚。导弹按"预计到达时间"排队，多门 CIWS 按最近者分配。
2. **概率：只在"已经对着导弹开火"时才掷骰**
   - 进入候选、分配到某门 CIWS，**不等于**开始判定。这门炮要先完成索敌反应（`react`），再按 3.3 节的转动模型把炮管转到解算方向。炮管夹角小于 `fireTol` 并且真的开始射击之后，才算"在打"。
   - 每门炮有一个"有效射击计时" `fireT`：只在本帧确实开火时（炮管对准、在射程和射界内、冷却完毕）才累加。每累加满 0.25 s 掷一次骰，然后从 `fireT` 里扣掉 0.25 s。
   - 导弹机动或横穿让炮管一时跟不上（夹角超过 `fireTol`），或短暂出了射界时，计时**暂停**、不清零。重新对准后接着累计。
   - 拦下一枚以后，转向下一枚还要重新转动和对准，这段时间不掷骰。所以多枚来袭时，后面的导弹天然地少挨几次判定，过载效应比原方案更强、也更真实。
   - 单次概率：
     ```
     p = P_BASE × speedK × aspectK
     P_BASE = 0.055                                   // 判定窗口被转动时间吃掉一截，基础值比原方案的 0.04 高
     speedK = clamp(600 / missile.speed, 0.5, 1.2)    // 越快越难打
     aspectK = 正对来袭 1.0，横穿 0.7
     ```
   - 估算：600 m/s 的导弹从 1800 m 打到 150 m，窗口约 2.75 s。扣掉反应和转动约 0.8 s，有效射击约 2.0 s，掷 8 次，单门拦截率约 36%。900 m/s 时窗口 1.83 s，扣掉 0.8 s 后掷 4 次，约 20%。从侧后方来、需要大角度转动的导弹会更低。这些数值以 probe-ciws 实测为准。
   - **过载**：门数少于来袭数时，多出来的导弹没有 CIWS 交战，直接突防。转火要花时间，进一步压低了齐射时的总拦截率。
3. **演出**：炮塔真实转向，对准后才开始持续发射 `fake:true` 曳光弹，和掷骰计时的起点一致，玩家看到开火就意味着已经在判定。曳光弹不参与 `scanShot`、不扣弹药或只扣象征性弹药，开销很低。判定成功后，导弹在 0.1–0.3 s 随机延迟后空爆（`Combat.blast`）。150 m 外空爆不会伤到本舰。
4. 拦截结果对玩家可见：自己的反舰弹被拦截时 HUD 提示 "INTERCEPTED"；我方舰队替玩家拦下导弹时 radio 播报。
5. 与 DEW 的关系：GUS-2 的逻辑不动，两者独立。
6. **与电子战压制的关系**：宿主舰被敌方干扰机压制时（`t.suppressed`，v1.13.x 起舰船也有这个值，已经按 `Ent.JAM_SURF_K = 0.5` 打过对折），近防也变差：
   - 单次概率再乘 `(1 − 0.6 × suppressed)`：火控雷达受扰，解算质量下降。
   - 索敌反应 `react` 乘 `(1 + suppressed)`：要更久才能确认目标。
   - 进入候选的距离不受影响。近防炮工作距离很近，基本都在舰船的烧穿距离（`Ent.JAM_BURN_SURF` 4500 m）以内，压不掉"看见"，只压"打准"。
   - 效果：干扰机伴随反舰攻击，能实打实地提高突防率。这是现实中反舰打击编组的标准做法。
   - probe-ciws 加一组：同样 2 枚来袭，`suppressed` 取 0 / 0.25 / 0.5，拦截率应单调下降。

### C · 舰船尾部螺旋桨水花

### 4.8 尾流水花特效
- 目标：舰船航行时，在 3D 模型尾部（螺旋桨位置）持续冒出白色翻滚水花，速度越快越明显，停船时消失。纯演出，不参与碰撞和伤害。
- 数据：`SHIPS[].props: [{ x, z }]`，螺旋桨在模型局部坐标的位置（通常在舰尾水线下方，单轴或双轴）。没写时按 `dim` 推导：舰尾 `-len/2 × 0.92`，双轴左右各 `beam × 0.18`。
- 生成：
  - 每艘舰每帧按 `rate = RATE_MAX × clamp(speed / maxSpeed, 0, 1)` 发射粒子，`RATE_MAX` 起步 30 个/秒/轴。航速低于 2 m/s 不发射。
  - 粒子出生在螺旋桨位置后方 2–4 m 的水面（y = 海面 + 0.3），带少量随机横向速度和向上初速（1–3 m/s），受重力落回水面。
  - 外观：白色 / 浅青色半透明圆片，出生时小、0.6–1.2 s 内放大 2–3 倍并淡出，形成从舰尾往后拖开的一道翻腾白带。
  - 远处降级：玩家距离 3 km 以外减半，6 km 以外只画一条简化的平面尾迹带或不画。粒子总数设上限（如全场 600），超出时丢最老的。
- 复用现有粒子 / 烟雾系统的池子，不新开渲染路径；如果现有系统只有烟雾，新增一个 `kind:'spray'` 分支，颜色和重力不同。
- 舰船受损沉没时停止发射；高速转向时外侧一轴的发射率 ×1.3，让转弯尾迹略不对称。
- 验证：smoke 跑一艘 Orca 全速航行 10 s，断言粒子数稳定在上限以下；截图检查舰尾有连续水花、停船后 2 s 内消失；帧时间与关闭特效时相比增加不超过 5%。

### D · 各势力固定式海上平台

### 4.9 海上平台单位
- 目标：给各势力加一批**固定不动**的海上平台，作为可被攻击的地表单位进入游戏数据、模型和图鉴。本阶段只要求"加入游戏"：能在图鉴里看到、能被任务脚本生成、能被打掉、能搭载炮塔；**暂不安排进任何关卡**。
- 数据：新表 `PLATFORMS`（`data.js`，结构对齐 `SHIPS`：id、model、name、cn、cls、faction、operator、role、dim、hp、radius、value、gunResist、vials、arms、desc），外加 `speed: 0` 与 `fixed: true`。生成时 `ttype:'ground'`，不走 route，不发射水花。
- 起步清单（每个主要势力 1–2 种，名字和设定后续可改）：

| id | 势力 | 类型 | 定位 | 武装（arms） |
|---|---|---|---|---|
| `shoal` 浅滩站 | 上游公约 | 导管架防空平台 | 前沿雷达 + 舰空弹，护住电缆与驳船 | 16 单元舰空弹垂发、近防炮 ×2 |
| `breakwater` 防波堤 | 上游公约 | 半潜补给平台 | 燃油 / 弹药中转，自身只有自卫火力 | 近防炮 ×1、50 mm 机炮 ×2 |

### E · 平衡回归与新关卡

### 4.10 平衡回归
- 玩家的反舰弹现在会被拦截。需要回归所有对舰关卡：增加任务给予的弹药量、降低舰船 hp，或接受"需要齐射"的新玩法。在 changelog 写明。
- m8 舰队防御：我方 CIWS 会帮玩家拦截，难度下降，相应增加敌方攻击波次。

### 4.11 新关卡（2 个起步）
1. **舰队对决**：双方各 5–10 艘，玩家支援我方舰队获胜。胜利条件为敌舰全沉，失败条件为我方旗舰沉没。双方舰队各自从射程外的距离触发，然后相互靠近，进入射程后也是一边射击一边靠近，直到一个足够近的距离停下。（不要贴脸那么近）。旗舰受损到几个程度会触发无线电消息。
2. **资产保卫**：敌舰炮击我方岸上或海上设施，资产 hp 归零前击退舰队。敌舰火力需要压到"玩家不管就 3–4 分钟内失守"。由于单位血量不可见，可以通过在指定几个血量百分比触发友军无线电的方式来提醒玩家目标血量。如果暂时做不出这种大血量资产，或者已有的设定空间内无法合理化这种资产（例如想写加强地下掩体，但目前游戏只有纯海域地图不可能有地下掩体），可以改为攻击固定资产集群，全灭前击退舰队。
- 目标资产已损失的血量/数量会减少关卡评分。 两个关卡写进 `MISSIONS`，并加入合适的 `CAMPAIGNS` 位置，然后跑 probe-

所有这类关卡里（如果已有关卡里也有友军也看看要不要改），友军，任务指定要保护的友军单位的损失对分数影响更大。

 ### 4.12 验证（近防与新关卡）
- **新工具 `tools/probe-ciws.js`**：单艘 Orca（2 门 CIWS）分别承受 1 / 2 / 4 / 8 枚同时来袭，各跑 200 次。期望拦截率依次约 55% / 45% / 25% / 12%（双门叠加时单枚约 55%；转火耗时让多枚来袭时下降得更快），确认过载曲线单调下降。另外断言三点：炮管未对准前不掷骰（首次掷骰时刻 ≥ 反应时间 + 转动时间）；跟丢时计时暂停、不清零；从正面来袭的拦截率高于从侧后方来袭。
- 手动：近防炮转向和曳光看起来像真的在打，空爆点在导弹航迹上。

### F · 舰船自身电子战（提议，未排期）

v1.13.x 的电子战压制已经覆盖舰船（见 `docs/systems/hud.md`）：
- 舰船自己受的压制打对折，烧穿距离 4500 m。被压时，舰空弹的锁定距离和可锁范围收缩。
- 玩家看舰船、锁舰船时，压制也打对折。

下面这些是以后可以做的方向，现在不做：
1. **舰载箔条 / 诱饵**：舰船对来袭反舰弹投放箔条云，复用 `breakLock` 的诱饵逻辑，诱饵对象换成舰船。导弹被骗以后追着箔条云起爆（v1.13 的诱饵起爆已经有了），溅射伤害看箔条投放的距离。投得太近，照样会溅到本舰。
2. **舰载干扰机**：大型舰（航母、驱逐舰）带一个小半径的 `ewFieldR`，压制附近的敌机，包括敌机的锁定距离和反舰弹的导引头。这样玩家打舰队时，也要先处理掉"电子战舰"，或者带上反辐射弹（`antiRadar`，对正在辐射的目标伤害翻倍）。
3. **压制降低近防拦截率**：见 4.7 第 6 条。
4. **数据链降级**：舰队里一艘被压制，它给编队共享的目标信息延迟或丢失。这块要等舰队协同（4.1 的目标选择）做完再说。
